# Начало работы: своя кампания на основе Качи

Эта инструкция рассчитана на человека, который умеет редактировать текстовый файл, но не знает Python, NDF и внутреннее устройство WARNO. Команды копируются в PowerShell; писать программный код не потребуется. Названия полей, допустимые значения и связи между файлами разобраны в [справочнике YAML](YAML_REFERENCE_RU.md), а готовые изменения — в [практических примерах](RECIPES_RU.md).

## 1. Установить рабочее окружение

Понадобятся Windows, установленная WARNO с официальными инструментами и 64-битный Python 3.11 или новее. Python — среда выполнения фреймворка; старый Python из `WARNO/Mods/Utils` не подходит. Если Python ещё нет, установите его с [официального сайта](https://www.python.org/downloads/windows/) с Python Launcher. Текстовый редактор должен сохранять UTF-8; подойдёт VS Code или другой привычный редактор. Графический редактор кампаний не нужен.

На странице GitHub выберите **Code → Download ZIP**, распакуйте архив в отдельную папку на диске с запасом места. Git также подходит, но для работы не обязателен. Не размещайте исходники внутри папки установленной игры.

Откройте эту папку в Проводнике, нажмите правой кнопкой и выберите открытие терминала/PowerShell. В терминале должны быть видны `README.md`, `scripts` и `campaigns`. Выполните:

```powershell
py -3 -m venv .venv
./.venv/Scripts/python.exe -m pip install -e .
```

После загрузки зависимостей все следующие команды используют созданное окружение. Каждый раз открывайте терминал в корне репозитория. Не выполняйте команды из папки `campaigns/kacha`.

## 2. Выбрать установленную игру

В Steam расположение можно открыть через свойства WARNO → «Установленные файлы» → «Обзор». Нужна папка, содержащая `WARNO.exe`, а не папка `Data` или `Mods`. В ней также должны быть `Mods/ModData/base.zip` и `Tools/AssetCooker.exe`.

```powershell
$game = 'C:/Program Files (x86)/Steam/steamapps/common/WARNO'
./.venv/Scripts/python.exe -B scripts/campaign.py prepare --game $game
```

Замените значение `$game` своим путём. Пробелы и кириллица допустимы в кавычках. Если открыли новый терминал, задайте `$game` снова.

Подготовка извлекает официальный каталог игры в `artifacts/modgen-201602-template` и создаёт локальные словари совместимости в `artifacts/compatibility`. Команда не запускает игру и не устанавливает мод. Повторный вызов использует каталог только при совпадении хеша игрового `base.zip`.

Адаптер рассчитан на совместимый формат ModGen 201602 и проверенные архивы. Это не обещание совместимости с любой будущей версией WARNO. При ошибке хеша не заменяйте ожидаемый хеш случайным: потребуется совместимый адаптер.

## 3. Получить самостоятельные исходники

Исходная Кача находится в `campaigns/kacha`. Для своего мода скопируйте её командой:

```powershell
./.venv/Scripts/python.exe -B scripts/campaign.py clone campaigns/kacha campaigns/my-campaign --id my_campaign
```

`my_campaign` — внутренний идентификатор: латинские строчные буквы, цифры и подчёркивания, первая буква; не более 48 символов. Название в меню может быть любым и задаётся отдельно.

Команда создаёт папку `campaigns/my-campaign`, меняет идентификаторы кампании, профиля и изображений, а также даёт копии отдельное имя карты. Оригинал остаётся нетронутым. Новый путь должен ещё не существовать. Своя карта получает отдельное имя даже при использовании исходной географии: будущие изменения не должны пересекаться с кэшем Качи.

## 4. Разобраться, что менять

| Задача | Файл |
| --- | --- |
| Название, дата, число ходов, стороны, победа, карточка в меню | `campaign.yaml` |
| Батальоны, роты, взводы, командиры и снабжение | `battalions/forces.yaml` |
| Конкретная пехота/машина, транспорт, опыт и число машин в одной карточке | `packs.yaml` |
| Начальные позиции, усталость, текущие ОД, потери и блокировка | `deployments.yaml` |
| Стартовые приказы ИИ | `ai.yaml` |
| Карточки подкреплений, ходы прибытия, точки высадки, условия выбора | `production.yaml` |
| Автоматическое появление отдельных наземных частей без карточки | `reinforcements.yaml` |
| Сообщения, два варианта решения, последствия | `events.yaml` |
| Аэродромы, авиакрылья, сроки появления и ухода | `aviation.yaml` |
| Флаги, фронт на старте, подписи, маршруты, типы клеток и дороги | `map.yaml` |
| Рельеф, фон карты, здания и деревья | `world.yaml` и `artwork/` |
| Вступление, концовки, стартовая камера | `cinematics.yaml` |
| Исходные картинки событий и двухкарточные коллажи | `event-images.yaml` |
| Собственные эмблемы | `emblems.yaml` |
| Переводы на остальные языки игры | `localization.yaml` |
| Размеры/границы карты и привязка к штатному формату | `profile.yaml` |

Наземный батальон описывается один раз и появляется **одним** способом: на старте, в карточке подкрепления, по событию или как автоматическое подкрепление. Авиакрылья появляются через `aviation.yaml`. Один батальон нельзя использовать в двух взаимоисключающих вариантах: копируйте определение с другим `id`.

Сначала измените название и состав одного батальона, затем переходите к сложным событиям или новой географии. После каждого связанного набора правок выполняйте проверку. Все форматы и ограничения указаны в справочнике; новые поля нельзя придумывать произвольно.

## 5. Найти названия юнитов и декалей

Не угадывайте внутренние идентификаторы по названию на карточке. Получите каталоги своей игры:

```powershell
./.venv/Scripts/python.exe -B scripts/campaign.py catalog --game $game --output artifacts/catalog-01
```

Откройте CSV в табличном редакторе или текстовом редакторе:

- `units.csv`: внутренний `id`, названия в игре на русском/английском, категория и теги. `id` используется в `packs.yaml` и `strategic.visual.unit`.
- `packs.csv`: готовые сочетания юнита, транспорта, опыта и количества. `id` отсюда используется как `type` в составе взвода.
- `scenery.csv`: реальные имена зданий/деревьев для `world.yaml.objects[].asset`.

Для просмотра проверенных вариантов транспорта:

```powershell
./.venv/Scripts/python.exe -B -m warno_ag editor-pack-options Naval_Rifle_SOV
```

Замените `Naval_Rifle_SOV` нужным внутренним ID. Наличие юнита в каталоге ещё не гарантирует, что любой транспорт подходит ему; выбирайте зарегистрированный вариант или явно задавайте проверенный транспорт в `packs.yaml`.

## 6. Проверить исходники

```powershell
./.venv/Scripts/python.exe -B scripts/campaign.py check campaigns/my-campaign --game $game --output artifacts/my-check-01
```

Проверка компилирует YAML, проверяет ссылки, состав, переводы, картинки и исходную сцену. Она пишет промежуточные данные, не запускает WARNO, не готовит играбельный мод и не меняет сохранения.

При ошибке исправьте названный файл/поле и повторите с новым номером выходной папки (`my-check-02`). Исходник не нужно создавать заново. Выходные каталоги специально не перезаписываются, чтобы сохранить отчёт о предыдущей попытке.

`campaign.compiled.json` — промежуточная модель. Редактировать надо YAML, а не этот JSON. Успешная проверка не подтверждает баланс, поведение ИИ или кооператив.

## 7. Собрать полноценный мод

Сохраните файлы и закройте WARNO перед полноценной сборкой. Официальный компилятор использует рабочие данные игры.

```powershell
./.venv/Scripts/python.exe -B scripts/campaign.py build campaigns/my-campaign --game $game --output artifacts/my-build-01
```

Команда сама готовит изображения событий, исходники стратегической карты, отдельный ModGen workspace, запускает официальную генерацию/запекание карты, готовит игровые ресурсы и проверяет полный пакет. На новой карте первый проход может занимать заметное время. Папку `artifacts` не надо загружать на GitHub.

Если остался кэш карты с таким же именем, но другой геометрией, сборка остановится, а не примет несовпадающие файлы. Измените `world.yaml.map_name` и `profile.yaml.strategic_map.map_name` на одинаковое новое имя, например `AGF_MyCampaignMap02`, и повторите в новом выходном каталоге. Обновляйте имя карты только при необходимости пересобрать изменившийся мир; исходники предыдущего мира и отчёты сохранятся.

В `artifacts/my-build-01/build-result.json` находится `package` с тремя важными путями:

| Поле | Что находится по пути |
| --- | --- |
| `candidate` | Полный собранный мод до установки |
| `bundle` | Проверенный неизменяемый пакет с манифестом и хешами |
| `config` | `campaign.compiled.json`, которым установщик определяет именно эту кампанию |

Не подставляйте примерные хеши из чужого отчёта. Используйте пути своей сборки.

## 8. Установить и сыграть

WARNO должна быть закрыта. Для первой установки:

```powershell
$result = Get-Content artifacts/my-build-01/build-result.json -Raw | ConvertFrom-Json
./.venv/Scripts/python.exe -B -m warno_ag full-install $result.package.bundle $result.package.config
./.venv/Scripts/python.exe -B -m warno_ag full-status $result.package.config
```

`full-install` сразу устанавливает **и активирует** полный пакет. Отдельной команды `full-activate` нет. Статус должен показывать `installed`, `active`, `owned` и `integrity_verified` как `true`.

Чтобы заменить уже установленную управляемую версию:

```powershell
./.venv/Scripts/python.exe -B -m warno_ag full-reinstall $result.package.bundle $result.package.config
```

Для удаления своего управляемого мода:

```powershell
./.venv/Scripts/python.exe -B -m warno_ag full-uninstall $result.package.config
```

Не копируйте отдельные `.dat` или картинки поверх установленной кампании. Это оставляет старые ресурсы и затрудняет диагностику. Не включайте местную Качу одновременно с её Workshop-версией; для обычного использования активируйте одну кампанию фреймворка.

Откройте WARNO и начните **новую** кампанию. Старое сохранение хранит прежний состав, события и состояние; обновление исходников не переписывает его. Проверьте обе стороны, варианты решений, подкрепления и окончание. Кача V17.2 проверена автором по четырём решениям; кооператив пока не подтверждён.

## 9. Подготовить Workshop

Подготовка отделена от публикации. Она создаёт исходно неопубликованный предмет с `ID = 0`:

```powershell
./.venv/Scripts/python.exe -B -m warno_ag workshop-export $result.package.bundle $result.package.config artifacts/my-workshop-01 --preview campaigns/my-campaign/artwork/workshop-cover.jpg
```

Создайте собственную JPG/PNG-обложку размером меньше 1 000 000 байт. В исходниках Качи нет универсальной Workshop-обложки для вашего предмета; изображение меню и обложка — разные назначения. Экспорт пишет `stage.json`, `preview` и папку `mod` с готовым содержимым. Не загружайте весь исходный репозиторий или `artifacts` как Workshop-контент.

Для обновления **своего** уже опубликованного предмета используйте проверенный `publication.json` предыдущей публикации через `--publication-receipt`. Не используйте номер Качи для своего мода. Штатный загрузчик WARNO и SteamCMD имеют отдельный процесс входа/публикации; фреймворк не получает ваш пароль. Встроенный `workshop_content_update.py` работает через запущенный Steam только для уже принадлежащего вам предмета и меняет только содержимое/обложку. Для первой приватной публикации предусмотрены `private_workshop_release.py` и `Run-PrivateWorkshopUpload.ps1`; их справка вызывается с `--help`.

Сборка самостоятельная: игроку достаточно подписаться на один предмет, включить мод и начать кампанию. Раздельная зависимость «кампания требует установленный фреймворк» этому способу не нужна.

## 10. Что делать при ошибке

| Сообщение/симптом | Что проверить |
| --- | --- |
| Python не найден | Установлен ли 64-битный Python и Python Launcher; повторите создание `.venv` |
| Поля не совпадают / `extra` / `missing` | Отступы, точное имя поля и таблицу соответствующего файла |
| `Duplicate YAML key` | Один ключ повторён в одном объекте; оставьте единственное определение |
| Неизвестный юнит, pack, флаг или battalion | Ссылку на `id`, правильный каталог и файл объявления |
| Батальон появляется более одного раза | Создайте отдельное определение для каждой возможной части |
| Название длиннее 30 UTF-16 | Сократите его во всех переводах; это ограничение коротких названий OOB, не текста события |
| Недостающий перевод | Обновите ключ после изменения английской строки в `localization.yaml` |
| Флаг конфликтует с influence | Передвиньте/добавьте источник фронта той же стороны рядом с флагом |
| Часть заблокирована с 0/0 ОД | Не задавайте постоянную ёмкость ОД равной нулю; используйте `frozen_turns`, затем новую кампанию |
| Картинка/эмблема не найдена | Относительный путь, зарегистрированный ID/token и соответствующий исходный PNG |
| Исходники карты не совпадают с кэшем | Новое согласованное имя карты в двух YAML, новый каталог результата |
| Несовместимая версия/хеш | Сохраните отчёт; нужен адаптер для установленной версии, а не произвольная замена хеша |
| Ошибка официальной генерации | Смотрите `build/editor-package-report.json` и подпапки с `process.json`; ошибка этапа не равна проверке YAML |
| ИИ не выполняет ожидаемый манёвр | Ссылка на правильный ID, начало хода, тип приказа, маршрут, состояние части и настройка штатного/скриптового управления |

Если файл результата уже существует после ошибки, не удаляйте его вслепую: сначала прочитайте отчёт. Для новой попытки используйте следующий номер. Сохранять на GitHub нужно YAML, нужные изображения, собственные материалы и атрибуцию. Игровые архивы, кэши, сохранения и собранные моды остаются локальными.
