# 3. Состав батальонов и собственные packs

[Навигатор](../RECIPES_RU.md) · [English](03-rosters.md) · [Поддержка](04-support.ru.md)

## Простой вариант: добавить машину или отряд

1. В `battalions/forces.yaml` найдите батальон по его корневому `id`.
2. В `definition.companies` выберите роту, затем взвод в `platoons`.
3. У нужной записи `units` увеличьте `count`, например с `3` на `4`.
4. Проверьте исходники, соберите мод и откройте состав в новой кампании.

```yaml
units:
- type: my_rifle_pack
  count: 4
```

Фрагмент находится внутри существующего взвода. `my_rifle_pack` замените настоящим ID имеющегося pack. Это ID сочетания юнита и транспорта, а не непосредственно тактического юнита.

```powershell
./.venv/Scripts/python.exe -B scripts/campaign.py check campaigns/my-campaign --game $game --output artifacts/roster-check-01
```

`count` задаёт число элементов состава. Сверьте `number` используемого pack: `count: 4` при `number: 2` представляет восемь юнитов. Название роты само по себе технику не выбирает.

## Заменить юнит или транспорт

Выгрузите каталоги установленной совместимой игры в новый каталог:

```powershell
./.venv/Scripts/python.exe -B scripts/campaign.py catalog --game $game --output artifacts/catalog-01
```

В `units.csv` найдите реальный тактический юнит. В `packs.csv` подберите сочетание юнита, транспорта, опыта и количества. В `type` записи взвода используется ID именно pack.

Если подходящего сочетания нет, добавьте в существующий список `packs.yaml.packs`:

```yaml
- id: my_rifle_btr60
  unit: Naval_Rifle_SOV
  transport: BTR_60_Naval_SOV
  experience: 1
  number: 1
```

После этого замените `type` нужного взвода на `my_rifle_btr60`. Примерные ID юнита и транспорта должны существовать в вашем каталоге. Для отсутствующего транспорта ставьте YAML `null`, а не строку `"null"`.

Для просмотра вариантов транспорта:

```powershell
./.venv/Scripts/python.exe -B -m warno_ag editor-pack-options Naval_Rifle_SOV
```

Инструмент проверяет существование юнита, транспортную классификацию и подходящую роль. Историческую уместность и игровой баланс он не оценивает.

## Изменить только один взвод

Pack — общее определение. Если на него ссылаются три взвода, правка затронет все три. Для локального улучшения:

1. Скопируйте полную запись собственного pack под новым уникальным ID.
2. Измените в копии `unit`, `transport`, `experience` или `number`.
3. Сошлитесь на новый ID только в выбранном взводе.

Для штатного pack создайте собственную запись по значениям каталога. Переопределять штатный ID нельзя: совпадение отвергается.

## Добавить или перестроить роты

Копируйте всю запись роты/взвода с обязательными именами, `hq` и вложенными списками. ID рот уникальны внутри батальона, ID взводов — внутри роты. В разных батальонах допустима рота с одним и тем же ID `rifle_1`.

У роты нужен хотя бы один взвод, у взвода — хотя бы одна запись юнита. При реорганизации перемещайте записи состава: изменение заголовка не переносит его содержимое. Командиров, снабжение и поддержку подбирайте под назначение части: [подробности](04-support.ru.md).

Для нового стратегического батальона скопируйте **весь** объект, дайте новый ID и выберите ровно один способ появления: [стартовое размещение](08-readiness.ru.md), [карточка резерва](05-reserves.ru.md), [автоматическое/событийное прибытие](06-events.ru.md) или [авиация](09-aviation.ru.md). Одно определение состава не появляется на карте автоматически.

## Параметры состава и packs

| Поле | Ограничения | Назначение |
| --- | --- | --- |
| Корень файла батальонов | `schema: 1`, `battalions: [...]` | Файлы внутри `battalions/` |
| `id` батальона | Уникальный строчный ID во всей кампании | Ссылка из размещения, прибытия и фаз ИИ |
| `side` | `nato`/`pact` | Коалиция |
| `definition.country` | Поддерживаемая страна из списка стороны | Национальная принадлежность и подставка |
| `definition.name`, `organization` | Непустые короткие строки ≤30 единиц UTF-16 | Основные названия в составе |
| `name_text`, `organization_text` | Необязательные короткие RU/EN | Явные локализованные названия |
| Рота: `id`, `name`, `hq`, `platoons` | Все обязательны; `hq` boolean, список непустой | Структура роты |
| Взвод: `id`, `name`, `hq`, `units` | Все обязательны; `hq` boolean, список непустой | Структура взвода |
| `name_text` роты/взвода | Необязательные RU/EN ≤30 UTF-16 | Переведённые заголовки |
| `units[].type` | Существующий ID pack | Юнит и транспорт |
| `units[].count` | Целое 1–100 | Число элементов состава |
| Собственный pack: `id` | Уникальный `[A-Za-z0-9_]+`, без совпадения со штатным | Имя нового сочетания |
| `unit` | Тактический ID из `units.csv` | Реальный боевой юнит |
| `transport` | ID зарегистрированного транспорта или `null` | Реальный транспорт |
| `experience` | Целое 0–3 | Штатный уровень опыта |
| `number` | Целое 1–10 | Юнитов в одном элементе |

У custom pack обязательны все пять полей. Ограничение коротких имён проверяется также для переводов: [локализация](12-localization.ru.md). Оно не ограничивает текст длинного брифинга.

## Подчинение и названия

Необязательное `definition.formation`:

```yaml
formation:
  division_id: coastal_brigade
  division_text: {ru: Береговая бригада, en: Coastal Brigade}
  regiment_id: coastal_regiment
  emblem: Texture_Division_Emblem_AGF_Coastal
```

`division_id`, `division_text`, `regiment_id` нужны вместе; `emblem` необязателен. Одинаковый division ID у частей одной стороны означает общие метаданные соединения: сохраняйте согласованные имя и эмблему. Собственный токен эмблемы сначала регистрируется; показанный токен не является встроенным ресурсом.

`organization_text` — полковое/организационное подчинение, `division_text` — общее вышестоящее соединение. Оба независимы от `campaign.menu.side_titles`.

## Стратегический вид и назначение

В `definition.strategic` обязательны `type`, `battle_role`, `visual`. Для наземных и вертолётных частей допустим `icon`; у самолётов значок выбирается по роли автоматически.

| Поле | Допустимые значения |
| --- | --- |
| `type` | `mechanized`, `helicopter`, `airplane` |
| `battle_role` | `fighter`, `ground_support`, `auxiliary_support`, `air_support` |
| `visual` | Предпочтительно `{unit: реальный_тактический_ID}` |
| `icon` наземной/вертолётной части | `Infantry`, `apc`, `ifv`, `Armor`, `Armor_heavy`, `HQ`, `reco`, `AA`, `AT`, `hel`, `howitzer`, `mlrs`, `assault` |
| Самолётный `aircraft_role` | `fighter`, `bomber`, `sead` |
| `support` | Радиус артиллерии/ПВО: [поддержка](04-support.ru.md) |

Пехотный батальон тоже использует стратегический `type: mechanized`; отдельного `type: infantry` нет. Вид и значок могут быть пехотными. `airplane` требует `air_support` и подходящий авиационный состав; наземные/вертолётные части не могут иметь `air_support`.

`visual` и `icon` меняют представление на стратегической карте, но не тактический состав. Packs и названия не меняют броню, оружие, тактическую скорость или стоимость юнита.

Старые пресеты вида: `west_german_infantry`, `east_german_infantry`, `west_german_armor`, `east_german_armor`, `soviet_armor`, `us_helicopter`. Для нового состава удобнее явный юнит каталога. Нормальные ОД и усталость — в [начальном состоянии](08-readiness.ru.md).

## Разбор ошибок

Неизвестный `type`: сверяйте каталог packs, а не только юнитов. Ошибка повторного использования батальона требует самостоятельного определения для каждого возможного экземпляра, даже взаимоисключающего. Изменение чужих взводов обычно связано с общим pack. Старая модель на карте после замены техники требует отдельной правки `strategic.visual`. Ошибка страны или авиационной роли исправляется согласованием стран, подставок и тегов юнитов, а не переименованием части.
