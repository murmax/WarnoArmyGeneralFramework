# 4. Командование, снабжение, артиллерия и ПВО

[Навигатор](../RECIPES_RU.md) · [English](04-support.md) · [Состав и packs](03-rosters.ru.md)

## Простой вариант: добавить снабжение батальону

1. Выгрузите каталоги через `scripts/campaign.py catalog`, если ещё не сделали этого.
2. В `units.csv` и `packs.csv` найдите машину снабжения и подходящий pack. Для прямого подсчёта машин удобен `number: 1`.
3. В нужном батальоне найдите штабную/поддерживающую роту и взвод.
4. Добавьте запись с настоящим ID pack и нужным количеством.
5. Проверьте исходники, соберите мод и откройте состав новой кампании.

```yaml
units:
- type: your_existing_supply_pack
  count: 10
```

Замените условное имя ID из каталога. Это запись списка юнитов взвода. Отдельного корневого поля `supply: 10` нет.

```powershell
./.venv/Scripts/python.exe -B scripts/campaign.py check campaigns/my-campaign --game $game --output artifacts/support-check-01
```

Способность снабжения даёт реальный юнит. Название взвода «Тыл» само по себе эту способность не создаёт.

## Командиры и штаб

`hq: true` у роты/взвода описывает место в структуре состава. Добавьте настоящие командные машины или командную пехоту соответствующими packs. Полную штабную роту можно копировать как основу структуры, затем заменить юниты под сторону и способ доставки.

Для роты с FOB и машинами добавьте pack настоящего FOB с `count: 1` и pack автомобиля с `number: 1`, `count: 10`. Сохраните обязательные ID, имена и `hq` взвода. FOB является обычным элементом состава, а не результатом специального названия роты.

Для вертолётной части подбирайте подходящие командные, транспортные и снабжающие юниты. Вертолётная модель на стратегической карте не превращает грузовики и наземных командиров в вертолёты. Реальный транспорт задаётся [packs](03-rosters.ru.md).

## Простой вариант: отдельная артиллерийская часть

В существующем `definition` батальона задайте роль поддержки и настоящий артиллерийский состав. Фрагмент заменяет настройки стратегии/состояния:

```yaml
strategic:
  type: mechanized
  battle_role: ground_support
  visual: {unit: 2S1_Gvozdika_Naval_SOV}
  icon: howitzer
  support: {kind: artillery, radius_ap: 12}
initial_state:
  fatigue: 0
  action_points: 5
```

Подбирайте и внешний вид, и packs по каталогу: показанная модель не задаёт состав. Для стартового размещения согласуйте `deployments.yaml.action_points`, например 5. Для подкрепления нормальные ОД/восстановление берутся из определения.

## Простой вариант: отдельное ПВО

Тип остаётся наземным, меняются реальный состав, роль и вид поддержки:

```yaml
strategic:
  type: mechanized
  battle_role: auxiliary_support
  visual: {unit: your_registered_aa_unit}
  icon: AA
  support: {kind: air_defence, radius_ap: 8}
initial_state:
  fatigue: 0
  action_points: 4
```

Условный `visual.unit` замените существующим ID. `radius_ap` измеряется в стратегической шкале клеток/ОД, а не в метрах или километрах. Согласуйте радиус с масштабом карты и позицией, а не с тактической дальностью ракеты.

Такая часть получает штатный приказ развёртывания/укрепления ПВО. Развёртыванием и активным прикрытием управляет игра. Само объявление поддержки не гарантирует оптимальное применение ИИ; проверяйте поведение игрока и ИИ в игре.

## Органическая и стратегическая поддержка

В обычный боевой батальон можно положить расчёты ПВО, ПТО, миномёты, саперов и снабжение. Они участвуют в его тактическом составе. Каждый содержащийся ствол не получает отдельный стратегический круг поддержки.

Независимая часть с `strategic.support` нужна для самостоятельного стратегического артиллерийского/зенитного юнита. Штабные взводы нужны для органической поддержки батальона. Эти механизмы можно сочетать.

Другие варианты: мобильный артдивизион, малоподвижное тыловое ПВО, снабжающий штаб дивизии, разведывательная вспомогательная часть или слабо оснащённая территориальная часть. Настраивайте реальный состав и подходящую роль, не предполагая способности по одному названию.

## Параметры и единицы

| Где | Значения/границы | Назначение |
| --- | --- | --- |
| `hq` роты/взвода | Boolean | Штабная структура, а не автоматическая командная способность |
| `units[].type` | Штатный/собственный pack | Реальный командир, снабжение, саперы или оружие поддержки |
| `units[].count` | Целое 1–100 | Элементов pack; количество учитывает `number` |
| `number` custom pack | Целое 1–10 | Юнитов в элементе; для точного счёта удобно 1 |
| `strategic.type` отдельной поддержки | `mechanized` | Требуется для нынешней артиллерии/ПВО |
| `strategic.battle_role` | Артиллерия: `ground_support`; ПВО: `auxiliary_support` | Стратегическая боевая функция |
| `strategic.support.kind` | `artillery`, `air_defence` | Вид поддержки |
| `strategic.support.radius_ap` | Конечное число >0 и ≤1000 | Стратегический радиус поддержки/прикрытия |
| `strategic.visual.unit` | Зарегистрированный ID | Модель на карте |
| `strategic.icon` | Поддерживаемый значок | При генерации поддержки выбирается howitzer/AA |
| `definition.initial_state.action_points` | Целое 0–12 | Нормальные начальные/восстанавливаемые ОД; для действующей части положительные |
| `definition.initial_state.fatigue` | 0–8 | Усталость определения/прибытия |
| `deployments[].action_points`, `fatigue` | Текущие стартовые ОД / усталость 0–8 | Первоначальное состояние на карте |

У `support` нужны оба поля `kind`, `radius_ap`. Текущий механизм отдельной артиллерии/ПВО не применяется к вертолётам или наземной роли fighter. Отдельных публичных параметров задержки развёртывания, тактической дальности ПВО, множителя боеприпасов поддержки и гарантированного применения нет.

## Как работает механизм

Фреймворк отдельно компилирует packs тактического состава и стратегические роль, движение, значок, теги и приказы. У артиллерии радиус становится штатным радиусом поддержки боя, у ПВО — радиусом запрета авиации с приказом развёртывания. Список оружия в роте сам по себе эти свойства не вычисляет.

Нормальные ОД определяют последующее восстановление. Текущие ОД стартового размещения задают первую позицию состояния. Разница и временные блокировки объясняются в [инструкции состояния](08-readiness.ru.md). Возможность участвовать в конкретном бою и подбор поддержки ИИ остаются решениями игры.

## Разбор проблем

Нет командиров: проверьте реальные юниты pack, а не `hq`. Неверное снабжение: посчитайте `count × number`. Нет стратегического прикрытия: проверьте роль, support и факт развёртывания. Неверный вид: отдельно измените `visual`. Поддержка не успевает: проверьте ОД, позицию и приказ; большой радиус не исправляет недоступное место. ИИ не применяет прошедшую check часть: проверяйте штатное поведение и [приказы](10-objectives.ru.md), не добавляя выдуманный ключ принудительного применения.
