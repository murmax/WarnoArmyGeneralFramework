# 13. Местность, OSM, высоты и объекты сцены

[Навигатор](../RECIPES_RU.md) · [English](13-geography.md) · [Свои файлы и подробности рендера](13-local-geodata.ru.md)

## Простой вариант: импорт другого района

Из корня репозитория в подготовленном окружении:

```powershell
./.venv/Scripts/python.exe -B -m warno_ag geodata-import 32.45 44.28 34.15 45.55 artifacts/my-geodata-01 --cache artifacts/geodata-cache --resolution 2048 --surface-size 4096 --elevation-ceiling-m 1200 --zoom 12
```

Замените четыре числа на **западную долготу, южную широту, восточную долготу, северную широту**. Это географический прямоугольник, не позиция части. Выходной каталог новый; кэш можно повторно использовать для совпадающих загрузок.

Команда скачивает высоты Copernicus и региональный OSM Geofabrik, затем рисует исходные изображения локально. Готовую кампанию она не создаёт и не устанавливает. Географический импорт требует окружения фреймворка и сети, запекание в кампанию — также штатных инструментов WARNO.

Основные результаты:

| Файл | Для чего |
| --- | --- |
| heightmap/heightmap.png | 16-битные высоты в ориентации игры |
| surface/surface.png | RGB-текстура карты |
| surface/strategic-grid-cells.json | Предварительные типы всей области 101×101 |
| osm/source.gpkg | Загруженные векторы |
| dem/dem-source.tif | Соединённый источник высот |
| surface/tile-mosaic.png | Собранное изображение рендера |
| geodata.json и отчёты | Реальные пути, границы, хеши и атрибуция |

## Простой вариант: подключить изображения

1. Скопируйте heightmap/surface в `campaigns/my-campaign/artwork/`.
2. Обновите относительные пути world.yaml.heightmap/surface.
3. Согласуйте геометрию world/profile. При изменении запекаемого источника задайте **новое одинаковое имя карты** в world.map_name и profile.strategic_map.map_name.
4. При наличии обновите georeference по отчёту. Перенесите флаги, подписи, части, аэродромы, резервы и waypoints под новый район.
5. Замените или очистите старые scenery objects: они за картинкой не перемещаются.
6. Обновите типы местности и дороги по разделу ниже. Старые правила движения не следуют новой текстуре.
7. Выполните check/build и проверьте ориентацию, берег, движение и высоты в новой кампании.

```yaml
# В world.yaml, остальные обязательные поля сохраняются
heightmap:
  file: artwork/heightmap.png
  max_altitude_lbu: 22
surface:
  file: artwork/surface.png
```

```powershell
./.venv/Scripts/python.exe -B scripts/campaign.py check campaigns/my-campaign --game $game --output artifacts/geography-check-01
```

Новый импорт имеет начало на **северо-западе**, север находится сверху: столбцы растут на восток по x, строки — на юг по y. Используйте высоты, поверхность и клетки вместе, без дополнительных переворотов. До версии 1.1.0 включительно генератор ошибочно выдавал карты югом вверх; старые проекты требуют отдельной согласованной миграции. Камера north_up исходные пиксели не преобразует.

## Три самостоятельных результата

| Результат | Где задаётся | Что делает |
| --- | --- | --- |
| Видимые цвета/дороги | world.surface.file | Внешний вид карты |
| Высоты, здания, деревья | world.heightmap, world.objects | Рельеф и объекты сцены |
| Типы движения и дороги | map.strategic_grid | Штатные типы клеток/дорожные признаки |

Нарисованная дорога не ускоряет движение, лесная клетка не создаёт деревья. Импорт рисует и классифицирует данные, но универсальной команды автоматической расстановки зданий/деревьев нет. Объекты задаются в world.objects. [Подробности](13-local-geodata.ru.md) отделяют автоматическое от авторского.

## Параметры команды

| Аргумент | По умолчанию / границы | Действие |
| --- | --- | --- |
| west/south/east/north | Четыре конечных числа | WGS84; долгота −180…180, широта строго −85…85, размер ≤3° по каждой оси |
| destination | Новый каталог | Результаты импорта |
| --cache | Обязательный каталог | Повторное использование загрузок и отчётов |
| --resolution | 2048; целое 128–8192 | Квадратная карта высот |
| --surface-size | 4096; целое 512–8192 | Квадратная поверхность |
| --elevation-ceiling-m | 1600; конечное 1–10000 м | Нормализация/ограничение высот |
| --zoom | 12; целое 8–13 | Детальность локального картографического рендера |

Промежуточная мозаика ограничена 48 000 000 пикселей. Высоты выбираются из 1–16 публичных тайлов, каждый до 300 000 000 байт; архив OSM до 500 000 000, извлечённый GeoPackage до 700 000 000. Выбирается один регион OSM: [покрытие и кэш](13-local-geodata.ru.md).

Разрешение и zoom меняют детальность, а не размер/число клеток движения. Высокий zoom может превысить промежуточный предел даже при конечной поверхности 4096.

## Геометрия и высоты мира

В корне обязательны schema agf-world/v1, id, map_name, bounds, render_cases, raster_axes, heightmap, surface, objects. Полная структура — [справочник](../YAML_REFERENCE_RU.md).

| Поле | Значения / правило |
| --- | --- |
| id | Уникальный строчный ID |
| map_name | Латинская буква, затем буквы/цифры/подчёркивания; совпадает с profile |
| bounds | `[0,0,max_x,max_y]`, положительные размеры |
| render_cases | Положительные целые width/height; блок по 655360 штатных единиц |
| raster_axes | columns_x_rows_y |
| heightmap.file | Относительная 16-битная grayscale PNG, оси 2–8192 |
| max_altitude_lbu | Конечное >0 и строго <5000/215 |
| Альтернатива высот | Прямоугольные samples ≥2×2, значения 0…1, resolution `[width,height]` 2–8192 и тот же предел |
| surface.file | Непрозрачная RGB PNG/WebP, оси 2–8192 |
| objects | Явный список; допустим [] |

Не смешивайте file и samples. Размер мира равен числу render_cases ×655360 по каждой оси. 2×2 означает `[0,0,1310720,1310720]`, playable area может быть меньше. Число блоков не равно 101×101 AP-клеткам или пикселям изображения.

Максимальный пиксель даёт высоту max_altitude_lbu ×215 штатных единиц. Рельеф строго ниже стратегического слоя 5000. Повышение DEM-ceiling уменьшает относительные высоты, понижение усиливает их с обрезанием пиков. Изменение world maximum меняет абсолютную высоту. Проверяйте оба параметра; не поднимайте всю карту ради читаемости гор.

Необязательная georeference содержит crs EPSG:4326, bounds_wgs84, elevation_ceiling_m 1–10000, строчный SHA256 источника из 64 hex-знаков и raster_origin northwest. Старое значение southwest читается для совместимости, но не вызывает автоматическую миграцию. Берите DEM-хеш из отчёта. Это происхождение/привязка, а не автоматическое перемещение юнитов.

Для неповёрнутого прямоугольника:

```text
x = min_x + (longitude - west) / (east - west) * (max_x - min_x)
y = min_y + (north - latitude) / (north - south) * (max_y - min_y)
```

Сначала проверьте узнаваемые ориентиры по углам. Размеры в градусах не равны физическим расстояниям: согласуйте пропорции мира с выбранным районом.

## Клетки движения и дороги

В map.strategic_grid нужны dimensions width/height, bounds, default_terrain. При наличии cells перечисляются **все** row/column ровно один раз. Необязательный ID соответствует r<row>c<column>; terrain берётся из default, road по умолчанию false.

```yaml
strategic_grid:
  dimensions: {width: 4, height: 3}
  bounds: [100000, 100000, 152000, 139000]
  default_terrain: StrategicPlain
```

Без cells это однотипная логическая сетка. Пример структурный: для своей карты держите bounds внутри playable_bounds и согласуйте размеры с profile. Здесь клетка 13000 игровых единиц; её размер не зависит от PNG.

Типы: StrategicPlain, StrategicForest, StrategicSemiUrban, StrategicUrban, StrategicWater. У полной записи клетки допустим road true, кроме блокирующей воды. Публичного StrategicMountain и произвольной стоимости дорожного ребра нет. Видимый рельеф самостоятельный.

Штатный AP-растр вычисляется по полному размеру карты и шагу 13000; авторские клетки проецируются на него. Импортный JSON — предварительные 101×101 всей области, его нельзя вставить без изменений в playable 48×55. Нужно выбрать/пересэмплировать нужный участок с перенумерацией либо сознательно задать полную сетку и согласованную геометрию. [Готовая процедура для полной карты](13-local-geodata.ru.md) приведена в подробностях.

## Здания и деревья

Выгрузите scenery.csv каталогом. В world.objects добавляются явные экземпляры:

```yaml
- id: town_building_01
  asset: your_registered_point_asset
  position: [877500, 331500]
  rotation_degrees: 90
  scale: 1
  ground_offset_lbu: 0
```

Замените asset поддерживаемым именем точечного объекта. Нужны уникальный строчный ID, позиция в границах, конечный угол 0–360, конечный положительный scale и конечный ground_offset. Обычно offset 0: штатная адаптация поднимает объект на рельеф, повторное прибавление высоты создаёт зависание над землёй.

Для плотности повторяйте разные экземпляры с разными координатами и согласуйте типы клеток. Произвольные штатные scenery patterns как point-объекты не поддерживаются. По картинке автоматически не выводятся высотные кварталы, тактическая городская плотность или бонус дороги.

В scenery.csv точечные регистрации имеют descriptor_class
`TSceneryDescriptorModel3D`, `TSceneryDescriptorMultiState`,
`TSceneryDescriptorMultiLOD` или `TSceneryDescriptorImpostor`. Выбирайте один
из этих классов, а не другую регистрацию pattern/graph.

## Разбор проблем

Зеркальная карта: до версии 1.1.0 включительно генератор ошибочно отражал север и юг. Новые импорты имеют начало northwest и север сверху; повторно переворачивать их нельзя. Для старого проекта одновременно переносятся поверхность, высоты, строки и границы клеток, все координаты объектов. Поворот камеры сам по себе отражение не исправляет. Водная клетка не совпадает с рисунком: исправьте предварительные маски. Старые объекты в новом районе: замените позиции сцены и остальных сущностей. Старый bake: одинаковое новое имя в world/profile и новый каталог сборки. Парящие здания: offset вместо повторной высоты. Плоские/пересекающие слой горы: нормализация отдельно от абсолютного потолка. Свои GeoTIFF/OSM и точные слои — [в подробной странице](13-local-geodata.ru.md).
