# 5. Карточки резервов и пункты развёртывания

[Навигатор](../RECIPES_RU.md) · [English](05-reserves.md) · [Условия](07-conditions.ru.md)

## Простой вариант: новый батальон на шестом ходу

В копии комплектного примера:

1. Скопируйте полный объект наземного батальона, например `sov_885`, в `battalions/`.
2. Дайте копии уникальный ID `my_reserve`, подходящие короткие имена и состав. Для этого примера оставьте `side: pact`.
3. Не добавляйте то же определение в deployments, автоматические подкрепления, spawn события или авиацию.
4. Добавьте запись ниже в существующий `production.yaml.groups`. Здесь используется имеющаяся дивизия `sov_810` и её точки.
5. Переведите новое имя карточки, выполните check/build и дойдите до хода 6 в новой кампании.

```yaml
- id: my_reserve_card
  division: sov_810
  name: {ru: Резервная группа, en: Reserve Group}
  turn: 6
  battalions: [my_reserve]
  ai: {type: defend, target: sevastopol}
```

```powershell
./.venv/Scripts/python.exe -B scripts/campaign.py check campaigns/my-campaign --game $game --output artifacts/reserve-check-01
```

Создаётся **карточка** запланированного резерва. Игрок развёртывает её через допустимые точки, ИИ использует план. Это не безусловное появление на конкретной координате. `my_reserve` — полное определение батальона, а не рота или pack.

## Несколько батальонов одной карточкой

Создайте независимые определения с уникальными ID:

```yaml
battalions: [reserve_rifle_1, reserve_rifle_2, reserve_tanks]
ai: {type: attack, target: sevastopol}
member_ai:
  reserve_rifle_2: {type: defend, target: belbek}
```

Все определения должны существовать и принадлежать стороне дивизии. Общий `ai` является основным планом, указанному члену задаётся свой. Карточка не сливает три состава в один батальон.

Батальон может создаваться один раз. Для альтернативных карточек тоже нужны отдельные определения: повторное перечисление `reserve_tanks` в другой группе запрещено. См. [условные варианты](07-conditions.ru.md).

## Собственный пункт и резервная дивизия

Добавьте пункт в `deployment_points`, дивизию в `divisions`, использующую её группу в `groups`. Фрагменты относятся к соответствующим существующим спискам:

```yaml
# deployment_points
- id: rear_depot
  side: pact
  position: [877500, 331500]
  name: {ru: Тыловой пункт, en: Rear Depot}

# divisions
- id: rear_reserve
  side: pact
  name: {ru: Резерв армии, en: Army Reserve}
  short_name: {ru: Резерв, en: Reserve}
  deployment_points: [rear_depot]

# groups
- id: rear_reserve_turn6
  division: rear_reserve
  name: {ru: Пехотный резерв, en: Infantry Reserve}
  turn: 6
  battalions: [my_reserve]
  ai: {type: defend, target: sevastopol}
```

Позицию выбирайте на доступной дружественной местности. Если используете этот вариант, уберите первую примерную группу: `my_reserve` не может быть в обеих. В корне сохраняются `schema: 1` и три обязательных списка.

Каждый пункт должен использоваться дивизией, каждая дивизия — группой. Устаревшие ссылки и неиспользуемые объявления удаляются вместе. У пункта автоматически появляется маленькая подпись; не создавайте вручную label с тем же автоматически получаемым ID `production_rear_depot`.

## Приоритет и территориальные условия

Несколько пунктов одной стороны перечисляются в порядке приоритета: желательный передовой первым, безопасный тыловой последним:

```yaml
deployment_points: [forward_depot, rear_depot]
required_flag: belbek
```

Объявите оба пункта. Необязательный `required_flag` ссылается на существующий флаг. Это **текущее** требование контроля стороной резерва: потерянный флаг ограничивает развёртывание, пока не возвращён. Игра также учитывает территорию и близость противника. Последний пункт должен действительно находиться в безопасном месте; порядок списка не гарантирует снабжение и свободную площадку.

Для постоянной отмены развёртывания после раннего захвата используйте `campaign.yaml.capture_deadline`. Там задаются флаг, захватывающая сторона, предел и дивизия; её группы не могут прибывать раньше предела. Подробности — [расписание](02-schedule.ru.md) и [цели](10-objectives.ru.md).

## Настройки

| Раздел | Поля и границы |
| --- | --- |
| Корень | `schema: 1`, списки `deployment_points`, `divisions`, `groups` |
| Пункт | Уникальный `id`, `side`, `[x,y] position` в profile.bounds, непустое RU/EN `name` |
| Дивизия | Уникальный `id`, `side`, RU/EN `name`, RU/EN `short_name`, непустой список разных `deployment_points` |
| Опция дивизии | `required_flag`: ID существующего флага |
| Группа | Уникальный `id`, существующая `division`, RU/EN `name`, `turn` 1…длительность, непустой список разных `battalions` |
| `ai` группы | `type`, существующий `target`, необязательный `route`: [миссии](10-objectives.ru.md) |
| `member_ai` | Непустое соответствие ID члена карточки → отдельный план |
| `when` | Непустой список требований к разным предыдущим решениям, соединённых И: [условия](07-conditions.ru.md) |

У пунктов, дивизий и групп отдельные пространства ID. Резервная дивизия production планирует карточки/точки, а `definition.formation` задаёт подчинение в составе. Даже когда они обозначают одно реальное соединение, это самостоятельные объявления.

Члены группы — полностью определённые наземные/вертолётные батальоны стороны дивизии. Самолёты не используют наземный production. Если хотя бы у одной группы есть `ai`, он нужен у всех; частичное включение направленного production не допускается. `member_ai` уточняет общий план, а не отменяет это требование.

Публичный формат не задаёт цену карточки, доход производства, повторяемые заводы, собственную валюту или выбор произвольной точки всей карты. Используйте объявленные сроки и пункты резервов.

## Устройство механизма

Компилятор создаёт штатные резервные дивизии, допустимые места появления и группы по срокам. При разрешённых сроке и решениях группа становится доступной. Игрок получает её в интерфейсе резервов. Направленный ИИ создаёт самостоятельные части в доступных пунктах и запускает общий/индивидуальные приказы. Информационные события существуют отдельно.

Усталость прибытия и нормальные ОД берутся из определения батальона. Отдельных production-полей `fatigue`/`action_points` нет: меняйте уникальный батальон. Уведомление может объявить карточку, но не должно создавать тот же батальон ещё раз.

## Разбор ошибок

| Симптом | Проверить |
| --- | --- |
| Карточки нет | Ход, разрешённость решений, весь `when`, ограничения дивизии |
| Карточка есть, поставить нельзя | Дружественный контроль, требуемый флаг, противника и точки |
| Повторное использование батальона | Ссылку из другой карточки или другого способа появления |
| Неиспользуемый пункт/дивизия | Удалить объявление или добавить нужную ссылку |
| Неправильный путь ИИ | Общий `ai`, `member_ai`, более поздние фазы батальона |
| Нет части внутри карточки | Полное определение и сторону; название состав не создаёт |

Проверяйте отдельно резервный интерфейс игрока и действия ИИ в новой кампании. Согласованное расписание исходников ещё не подтверждает допустимость каждого развёртывания в игре.
