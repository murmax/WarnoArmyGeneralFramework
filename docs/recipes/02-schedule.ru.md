# 2. Продолжительность, дата и расписание

[Навигатор](../RECIPES_RU.md) · [English](02-schedule.md)

## Простой вариант: продлить кампанию

1. В `campaign.yaml` измените `turns`, например с `20` на `24`.
2. Сохраните прежние сроки прибытия, если они по-прежнему подходят.
3. Проверьте исход по дедлайну в `victory.time_limit` и текст про доступное время операции.
4. Проверьте исходники в новом каталоге результата, соберите полный мод и начните новую кампанию.

```yaml
turns: 24
```

```powershell
./.venv/Scripts/python.exe -B scripts/campaign.py check campaigns/my-campaign --game $game --output artifacts/schedule-check-01
```

Продление не переносит резервы, авиацию, решения и смену приказов. Сокращение может оставить события за пределами допустимых ходов, что вызовет ошибку проверки.

## Простой вариант: перенести одно подкрепление

Найдите его группу в `production.yaml.groups` и измените реальное поле:

```yaml
turn: 6
```

Цифры в `id` являются частью имени. Переименование группы в `turn_6` не меняет её расписание.

Если прибытие сопровождается уведомлением, отдельно измените `events.yaml.trigger.turn` и текст. Если есть `when`, связанные решения должны происходить не позже прибытия. Правило раннего захвата может требовать более позднего минимального хода.

## Согласованное расписание

Перед большой правкой составьте таблицу: решения, прибытия, уход частей, смена приказов. У каждой строки укажите файл и зависимости. Обычно удобно рассматривать цепочку: стартовые силы → решение → условные резервы → новая фаза ИИ → уход части → дедлайн.

Можно дать несколько карточек на одном ходу, объединить несколько батальонов в одну карточку, перенести автоматическое появление, изменить сроки авиации или позже переназначить маршрут. Каждое действие настраивается своим полем; сюжетный текст его не планирует.

## Все настройки времени

| Файл и путь | Допустимо | Назначение |
| --- | --- | --- |
| `campaign.yaml.turns` | Целое ≥2 | Лимит ходов |
| `campaign.yaml.date` | Четыре целых `[year,month,day,period]` | Начальная дата и штатный период суток |
| `campaign.yaml.victory.time_limit` | `draw`, `nato`, `pact` | Исход по лимиту при заданной политике победы |
| `campaign.yaml.capture_deadline.before_turn` | 2…`turns` | Предел раннего захвата для блокировки дивизии |
| `production.yaml.groups[].turn` | 1…`turns` | Доступность карточки резерва |
| `reinforcements.yaml.reinforcements[].turn` | 1…`turns` | Автоматическое появление наземной части |
| `events.yaml.events[].trigger.turn` | 1…`turns` | Ход стороны-получателя для датированного события |
| `at_turn` эффекта spawn | Позже датированного trigger, не позже `turns` | Отложенное появление после события |
| `aviation.yaml.wings[].available.turn` | 1…`turns` | Прибытие авиакрыла по сроку |
| `available: {event,choice}` | ID решения и индекс 0/1 | Прибытие после решения, а не отдельная дата |
| `withdraw_turn` крыла | Внутри кампании, после датированного прибытия | Удаление этого авиакрыла |
| `ai.yaml.orders[].start_turn` | Целое ≥1 | Старт миссии начальной части; выбирайте ход внутри кампании |
| `ai_policy.phase_orders.<battalion>[].from_turn` | Строго возрастающие 1…`turns` | Смена плана батальона |
| `ai_policy.aggressive_until.<side>` | 1…`turns`, нужны обновляемые миссии | Конец агрессивного боевого профиля миссий |
| `deployments[].frozen_turns` | Неотрицательное целое | Число заблокированных ходов владельца; [состояние частей](08-readiness.ru.md) |

Четвёртое число `date` — штатный период суток, а не час вроде `16`. В комплектном примере `2` соответствует полудню. Отдельного поля длительности хода в часах и собственной таблицы периодов суток в публичном формате нет. Проверка формы принимает четыре целых: используйте настоящую календарную дату и известный период шаблона. Невозможная дата не обязательно будет обнаружена проверкой исходников.

## Зависимости сроков

**Предыдущие решения.** Для `when` нужны датированные события с двумя вариантами, происходящие не позже потребителя. Потребитель ждёт разрешённого решения; отдельного таймера условие не создаёт. См. [условные варианты](07-conditions.ru.md).

**Ранний захват.** Группы дивизии из `capture_deadline` не могут прибывать раньше `before_turn`. Ранняя блокировка закрепляется постоянно. При переносе резерва раньше согласуйте также предел захвата и уведомления. Уведомление `not_blocked` допускается с хода предела или позже.

**Уход авиации.** `withdraw_turn` требует известного более раннего прибытия. Для крыла после выбора датированным должно быть само решение. Выбор по недатированному захвату не задаёт корректный фиксированный срок ухода.

**Отложенные наземные эффекты.** `at_turn` поддерживается у spawn датированных событий и должен быть позже trigger. Это не универсальный ключ задержки для очков, потерь, ОД или самолётов.

**Фазы ИИ.** `from_turn` строго возрастает. Цели и маршруты ссылаются на объявленные флаги/waypoints. Перенос даты маршрут не создаёт. Подробнее — [цели и ИИ](10-objectives.ru.md).

## Устройство механизма

Компилятор создаёт штатные условия хода, состояния решения и одноразовые цепочки действий. Группа резерва, уведомление и авиакрыло — самостоятельные действия, даже если их названия похожи. Их расписание задают собственные поля. Фраза «завтра» в тексте не создаёт прибытия.

Номер хода соответствует стратегическому состоянию игры. Событие стороны дополнительно проверяет, чей это ход. `frozen_turns` отсчитывает блокировку по ходам владельца, а не по реальному времени. Для точных обещаний в часах сначала проверьте календарь собранной кампании в игре.

## Типичные проблемы

| Проблема | Что сделать |
| --- | --- |
| Сокращённая кампания не проходит check | Сверить все прибытия, эффекты, фазы и уходы с `turns` |
| Подкрепление перенесено, уведомление старое | Отдельно исправить уведомление и переводы |
| Резерв недоступен вовремя | Проверить решения, флаговые условия и допустимость точек развёртывания |
| Авиация осталась после уведомления | Поставить `withdraw_turn` каждому нужному крылу |
| ID содержит нужный ход, но срок не меняется | Изменить число `turn` |
| Старое сохранение использует прежнее расписание | Начать новую кампанию |

Перед выпуском проиграйте границы решений/прибытий и дедлайн. Корректность исходников ещё не устанавливает желаемый игровой баланс.
