# 11. Иллюстрации, карточки выбора и эмблемы

[Навигатор](../RECIPES_RU.md) · [English](11-artwork.md) · [Вступления и концовки](10-objectives.ru.md)

## Простой вариант: заменить имеющуюся картинку

1. Найдите логический `image` события/слайда в `events.yaml` или `cinematics.yaml`.
2. Найдите этот ID в `event-images.yaml.images`.
3. Замените локальный файл по указанному относительному пути, сохранив имя и ID.
4. При необходимости сохраните авторство/лицензию в `ASSET_CREDITS.md`.
5. Выполните check/build и откройте представление в новой кампании.

```powershell
./.venv/Scripts/python.exe -B scripts/campaign.py check campaigns/my-campaign --game $game --output artifacts/artwork-check-01
```

Сохранение ID позволяет не менять всех потребителей. Замена файла без сборки не обновляет установленный банк текстур.

## Новая логическая картинка

Добавьте файл, например `artwork/events/reserve.png`, и запись в `event-images.yaml.images`:

```yaml
reserve_picture: artwork/events/reserve.png
```

Для namespace `my_campaign` зарегистрируйте тот же ID в `profile.yaml.event_images`:

```yaml
reserve_picture: AGF_EVT_my_campaign_reserve_picture
```

В событии/слайде используйте `image: reserve_picture`. Файл, логический ID, namespace и токен — связанные элементы. URL сохраняет происхождение, но не заменяет локальный файл. Пути относительны корню кампании и не содержат выходов через `..` или абсолютного пути.

## Две иллюстрированные карточки

Объявите обе исходные картинки и составное изображение:

```yaml
schema: agf-event-images/v2
namespace: my_campaign
images:
  reserve_left: artwork/events/reserve-left.png
  reserve_right: artwork/events/reserve-right.png
composites:
  reserve_cards:
    kind: two_cards
    cards: [reserve_left, reserve_right]
```

Добавляйте в существующий документ, сохраняя остальные картинки. Зарегистрируйте в profile токены всех используемых ID, включая composite. У события `image: reserve_cards`, `layout: graphic_cards`; у первого варианта:

```yaml
card:
  image: reserve_left
  title: {ru: Первый вариант, en: First Option}
  text: {ru: Краткое описание варианта., en: A short description of the option.}
```

У второго — reserve_right. Первый источник composite соответствует левой карточке/choice 0, второй — правой/choice 1. Label и effects вариантов остаются обязательными. Текст задаётся локализованными полями интерфейса; запекать его в PNG не требуется. Картинка эффект решения не меняет.

Обычное изображение с текстом может быть одиночным. `plain: {some_id: text_choice}` создаёт служебный фон, а не фотографию или автоматически нарисованный сюжет. Composite ссылается только на исходные изображения, не на другие composites.

## Изображение меню

`campaign.yaml.menu.image` — относительный путь к **широкой PNG**, а не логический event-ID. Ширина 400–4096, отношение сторон 1,5–2,5. Компилятор готовит пропорциональную текстуру шириной 400 пикселей.

```yaml
image: artwork/menu-map.png
```

Поле находится внутри menu. Обложка Steam Workshop — другой файл: PNG/JPG/JPEG меньше 1 000 000 байт. См. [распространение](14-build.ru.md).

## Собственная эмблема соединения

Добавьте PNG в `artwork/emblems/` и объявите `emblems.yaml`:

```yaml
schema: 1
emblems:
- token: Texture_Division_Emblem_AGF_Coastal
  image: artwork/emblems/coastal.png
```

В `definition.formation` батальона:

```yaml
emblem: Texture_Division_Emblem_AGF_Coastal
```

Остальные обязательные formation-поля сохраняются: division_id, division_text, regiment_id. У членов одного соединения эмблема согласована. Собственному токену нужно объявление, штатному — существующий ресурс установленной игры. SVG-оригинал можно сохранять как источник, но на вход нужен локальный PNG.

Национальные/коалиционные флаги и подставки — другие штатные ресурсы. Эмблема бригады их не заменяет. Публичный формат задаёт символику соединения, а не произвольное переопределение национального флага.

## Все ограничения изображений

| Вход | Формат и ограничения |
| --- | --- |
| Корень event-images | agf-event-images/v2, namespace, images; необязательные composites/plain |
| Namespace и логические ID | Строчная буква, далее строчные буквы/цифры/подчёркивания, ≤48 знаков |
| Исходные event-изображения | Статичные RGB/RGBA PNG или WebP, оси 2–8192 |
| Composites | Уникальные ID, kind two_cards, ровно два ID исходных картинок |
| Plain | Логический ID → text_choice |
| Токен в profile | AGF_EVT_<namespace>_<logical_ID>, совпадающий с объявлением |
| Источник меню | Широкая PNG, ширина 400–4096, отношение 1,5–2,5 |
| Корень emblems | schema 1, список точных записей token/image |
| Токен собственной эмблемы | Уникальный Texture_Division_Emblem_AGF_[A-Za-z0-9_]+ |
| Эмблема | PNG от 64×64, файл ≤4 000 000 байт; удобна квадратная прозрачная |
| Файл авторства | UTF-8 ASSET_CREDITS.md, ≤256 КБ |

Старый event-schema v1 поддерживает только оригинальные картинки; для составных решений используйте v2. Surface/heightmap мира имеют отдельные правила формата и ориентации в [географии](13-geography.ru.md). Правила event-RGBA к ним не применяются.

## Как работает механизм

Check подготавливает исходные и составные изображения. Полная сборка обрабатывает частные текстуры и регистрирует токены в банках мода. Штатные представления заполняют именованные поля картинки/текста по декларациям события или слайда. Просто существующего локального файла без токена/ссылки недостаточно.

Эмблемы получают отдельный путь ресурса и ссылки подчинения. Обработку выполняет helper: вручную редактировать TGV/NDF не требуется. Сохраняйте оригиналы и условия использования для последующих сборок.

## Разбор проблем

Нет текстуры: путь, логический ID, токен profile, ссылка потребителя. Не та парная картинка: порядок composite и card.image. Старое изображение: пересоберите, начните новую кампанию. Не изменилась эмблема: проверьте formation, а не event-images. Перепутаны меню и обложка: используйте разные входные поля. Текст перекрывает изображение: сокращайте подписи и используйте нужный layout; размер PNG не меняет границы текстового поля.
