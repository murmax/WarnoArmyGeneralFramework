# 14. Проверка, сборка, установка и распространение

[Навигатор](../RECIPES_RU.md) · [English](14-build.md) · [Подробности Workshop](14-workshop.ru.md)

## Простой вариант: проверить и собрать

В корне репозитория с установленным окружением и копией исходников:

```powershell
$game = 'C:/Program Files (x86)/Steam/steamapps/common/WARNO'
./.venv/Scripts/python.exe -B scripts/campaign.py check campaigns/my-campaign --game $game --output artifacts/my-check-01
./.venv/Scripts/python.exe -B scripts/campaign.py build campaigns/my-campaign --game $game --output artifacts/my-build-01
```

Замените путь к игре. Каждой попытке нужен новый результат, например суффикс 02. Build тоже подготавливает/проверяет входы, но отдельный check быстрее сообщает ошибки до штатной генерации. Ни одна команда мод не устанавливает и не активирует.

После успешной сборки откройте artifacts/my-build-01/build-result.json. В package:

| Поле | Значение |
| --- | --- |
| candidate | Полные собранные файлы мода |
| bundle | Проверенный неизменяемый пакет с манифестом |
| config | Скомпилированная модель/идентичность для этого пакета |

Bundle и config берутся **из одной сборки**. Папка неудачной попытки без успешного конечного результата не является релизом для установки.

## Простой вариант: установить и сыграть

Сначала закройте WARNO. Используйте пути отчёта:

```powershell
$result = Get-Content artifacts/my-build-01/build-result.json -Raw -Encoding UTF8 | ConvertFrom-Json
./.venv/Scripts/python.exe -B -m warno_ag full-install $result.package.bundle $result.package.config
./.venv/Scripts/python.exe -B -m warno_ag full-status $result.package.config
```

Full-install **устанавливает и активирует**. Отдельной full-activate в этом CLI нет. Status должен показать installed, active, owned, integrity_verified true.

Начните новую кампанию: сохранения содержат прежние составы, действия и состояние. YAML их не мигрирует. Обычно активируют одну кампанию фреймворка; локальную и Workshop-копию одного сценария одновременно не включайте.

## Обновить или убрать управляемую установку

После следующей успешной сборки загрузите новый отчёт:

```powershell
$result = Get-Content artifacts/my-build-02/build-result.json -Raw -Encoding UTF8 | ConvertFrom-Json
./.venv/Scripts/python.exe -B -m warno_ag full-reinstall $result.package.bundle $result.package.config
./.venv/Scripts/python.exe -B -m warno_ag full-status $result.package.config
```

Для удаления этой кампании из локального каталога:

```powershell
./.venv/Scripts/python.exe -B -m warno_ag full-uninstall $result.package.config
```

Используются записи владения/транзакций. Предыдущий пакет может сохраняться в транзакционном каталоге для восстановления; это не удаление исходников, сейвов или всех кэшей. Не накладывайте избранные файлы поверх установленного мода и не меняйте его ownership-receipt вручную.

## Команды и аргументы

| Команда | Обязательные аргументы | Результат |
| --- | --- | --- |
| scripts/campaign.py prepare | --game | Подготовка/проверка каталога и словарей |
| clone | source, новый destination, --id | Самостоятельные ID кампании/профиля/карты |
| catalog | --game, новый --output | units.csv, packs.csv, scenery.csv |
| check | source, --game, новый --output | Модель и подготовленные входы мира/картинок |
| build | source, --game, новый --output | Полная штатная сборка, build-result.json |
| -m warno_ag full-install | bundle, config; необязательный --mod-parent | Полная установка/активация |
| full-reinstall | bundle, config; --mod-parent | Замена управляемой установки |
| full-status | config; --mod-parent | Владение, активация, целостность |
| full-uninstall | config; --mod-parent | Удаление управляемой локальной кампании |

Source — каталог с campaign.yaml/profile.yaml, а не имя YAML-файла. --game — каталог WARNO.exe и штатных инструментов. Пути с пробелами заключаются в кавычки. --mod-parent — общий родитель локальных модов, а не папка кампании; передавайте один и тот же при всех действиях установки. Default — Saved Games/EugenSystems/WARNO/mod текущего пользователя.

Clone требует другой строчный ID из 1–48 символов с буквы и новый каталог вне оригинала. Для обычного обновления той же независимой кампании клонирование повторно не нужно.

## Что выполняют check и build

Helper подготавливает каталог выбранной игры, проверяет YAML, ссылки, составы, переводы, изображения и входы мира. Check кампанию не запускает. Build дополнительно создаёт изолированную рабочую папку штатного компилятора, генерирует/запекает карту при необходимости, обрабатывает ресурсы и сверяет полный мод со скомпилированной моделью.

Отчёты/промежуточные файлы находятся в выбранном artifacts, компиляторные папки — artifacts/compiler-workspaces. Не загружайте весь этот каталог как мод. Размер сырых исходников/кэша не равен размеру финального пакета.

Адаптер привязан к совместимой структуре 201602 и идентичностям архивов. Нужны WARNO.exe, Mods/ModData/base.zip, AssetCooker и штатные инструменты. При несовместимости нужен подходящий адаптер, а не подмена проверяемого хеша.

Изменённый запекаемый мир получает новое одинаковое map_name в world/profile. Старый bake с тем же именем и другим источником отвергается. Новый каталог результата сам по себе не разрешает конфликт идентичности карты.

## Что смотреть в игре

Начните с изменённой функции и её связей: язык/названия, составы/транспорт, восстановление ОД/блокировки, сроки и точки появления, все варианты решений, приказы ИИ, контроль, авиация, дедлайн и концовки. Проверяйте нужные стороны. Кооперативный показ требует отдельной сетевой проверки: одиночное событие его не подтверждает.

Корректный YAML, успешная обработка ресурсов и совпадение скачанных байтов отвечают на разные вопросы и не являются подтверждением игрового поведения. Check не оценивает интересность, историчность и баланс.

## Подготовка Workshop

Из того же проверенного результата:

```powershell
./.venv/Scripts/python.exe -B -m warno_ag workshop-export $result.package.bundle $result.package.config artifacts/my-workshop-01 --preview campaigns/my-campaign/artwork/workshop-cover.jpg
```

Обложка PNG/JPG/JPEG меньше 1 000 000 байт. Экспорт содержит stage.json, preview и дерево mod с начальным Workshop ID 0. Это ещё не публикация. [Подробная инструкция](14-workshop.ru.md) объясняет приватную первую загрузку, subscriber-receipts и обновления с сохранением метаданных.

Готовая кампания для игроков самостоятельна: подписка/активация в WARNO без Python и отдельной установки фреймворка. Автор получает собственную идентичность Workshop.

## Ошибки

| Ошибка/симптом | Проверить |
| --- | --- |
| Каталог уже есть | Прочитать старые отчёты, выбрать новый путь |
| Лишние/неточные/повторные поля YAML | Имя, вложенность, единственный блок |
| Неизвестный юнит/pack/цель | Каталог и объявленный ID |
| Повторное создание батальона | Независимое определение на каждый экземпляр |
| Нет перевода/длинное имя | Точный EN-ключ и разрешённое короткое имя каждого языка |
| Флаг не согласован с влиянием | Ближайший источник нужной стороны |
| Нет картинки | Относительный файл, ID, токен, потребитель |
| Конфликт bake | Новое одинаковое имя в обоих файлах |
| Несовместимая версия/хеш | Совместимые игра/адаптер; сохранить ошибку |
| Ошибка штатной генерации | build/editor-package-report.json и process.json этапа |
| Нет владения/нарушена целостность | Совпадающие build/config и исходный receipt, без наложения файлов |
| Правки не видны | Нужная активная полная сборка и новая кампания |

В проекте исходников храните YAML, необходимые оригиналы и атрибуцию. Генерируемые игровые архивы, кэш, установки и сейвы отдельно. Установка окружения — [начало работы](../GETTING_STARTED_RU.md), точные схемы — [справочник](../YAML_REFERENCE_RU.md).
