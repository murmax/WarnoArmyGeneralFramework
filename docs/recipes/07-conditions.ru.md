# 7. Сложность и условные варианты сил

[Навигатор](../RECIPES_RU.md) · [English](07-conditions.md) · [События](06-events.ru.md) · [Резервы](05-reserves.ru.md)

## Простой вариант: карточка зависит от решения

В комплектном примере уже есть решения `nato_difficulty`, `pact_difficulty`. В вашей копии добавьте выбранной группе production:

```yaml
when:
- {event: nato_difficulty, choice: 0}
- {event: pact_difficulty, choice: 1}
```

Карточка доступна только при **первом** варианте первого решения и **втором** варианте второго. Требования выполняются одновременно. Сохраните остальные поля группы: срок, батальоны, дивизию и план ИИ.

```powershell
./.venv/Scripts/python.exe -B scripts/campaign.py check campaigns/my-campaign --game $game --output artifacts/condition-check-01
```

Пробуйте нужные исходы в новой кампании. Индекс задаёт положение элемента в `choices`, а не написанная на кнопке строка.

## Собственный выбор сложности

Для другого сценария добавьте обычное датированное событие с двумя вариантами:

```yaml
- id: operation_difficulty
  side: nato
  trigger: {turn: 1}
  title: {ru: Сложность операции, en: Operation Difficulty}
  text: {ru: Выберите уровень сложности., en: Choose the difficulty level.}
  image: difficulty_cards
  layout: text
  ai_choice: 0
  effects: []
  choices:
  - label: {ru: Обычная, en: Normal}
    effects: []
  - label: {ru: Сложная, en: Hard}
    effects: []
```

Зарегистрируйте `difficulty_cards`: [изображения](11-artwork.ru.md). Добавьте хотя бы один реальный production-потребитель `when`. При потреблении решения production немедленные эффекты могут быть пустыми. Полностью бессодержательный выбор без потребителя не является полезным допустимым событием.

Решение получает сторона события. На кого оно влияет, определяет сторона батальонов потребителя: решение НАТО может ограничить резервы PACT и наоборот. Страну этих юнитов решение не меняет.

`ai_choice: 0` выбирает первый вариант для ИИ. Это заданная автором политика, а не скрытый множитель сложности. Для иного двухвариантного игрового решения допустим и `1`, если именно он должен быть ответом ИИ.

## Заменить один вариант войск другим

Создайте два самостоятельных определения и две карточки:

```yaml
- id: armor_normal_card
  division: your_existing_division
  name: {ru: Бронегруппа, en: Armor Group}
  turn: 6
  battalions: [armor_normal]
  ai: {type: attack, target: your_existing_objective}
  when: [{event: operation_difficulty, choice: 0}]
- id: armor_hard_card
  division: your_existing_division
  name: {ru: Усиленная бронегруппа, en: Reinforced Armor Group}
  turn: 6
  battalions: [armor_hard]
  ai: {type: attack, target: your_existing_objective}
  when: [{event: operation_difficulty, choice: 1}]
```

Условные имена дивизии/цели замените объявленными ID. `armor_normal`, `armor_hard` — отдельные составы одной стороны. Меняйте их реальные packs/counts. Названия «Обычная»/«Усиленная» механического действия не имеют.

Можно выбирать меньше батальонов, более позднее прибытие, другую технику или отдельные приказы членов карточки. Каждый возможный экземпляр требует уникального определения, включая одинаково оснащённую поддержку альтернативных карточек.

## Два решения: сначала таблица исходов

| A | B | Условие примерной группы |
| --- | --- | --- |
| 0 | 0 | A=0 И B=0 |
| 0 | 1 | A=0 И B=1 |
| 1 | 0 | A=1 И B=0 |
| 1 | 1 | A=1 И B=1, если сочетание предусмотрено |

Объявите независимые группы для нужных случаев. Если нет подходящей группы, резерв не предоставляется; автоматического возврата к обычной карточке нет. Если подходит несколько групп, доступны могут быть все. Для замены, а не добавления, условия должны быть взаимоисключающими.

Оператора ИЛИ у `when` нет. Для A=0 ИЛИ B=0 перечисляйте нужные непересекающиеся случаи отдельными группами и составами. Один ID события нельзя повторять в одном списке, в том числе требуя оба его варианта одновременно.

## Условные уведомления и другие потребители

Датированное уведомление получает `when` внутри trigger:

```yaml
trigger:
  turn: 6
  when: [{event: operation_difficulty, choice: 1}]
```

Так можно объяснить вариант войск, не создавая их повторно. У полного события остаются обязательные title, text, image, choices, effects. Авиация после выбора использует `available: {event: ..., choice: ...}` — это отдельная форма доступности, а не список `when`.

## Параметры и ограничения

| Настройка | Требование |
| --- | --- |
| `choices` решения | Ровно два варианта с локализованной label и списком effects |
| `ai_choice` | Целое 0/1, по умолчанию 0 |
| `when` группы production | Непустой список точных записей `{event,choice}` |
| `trigger.when` события | Такой же формат, только при `trigger.turn` |
| `event` требования | Существующее двухвариантное событие с датой |
| `choice` | Целое 0/1 |
| ID событий списка | Все разные |
| Сроки | Источник решения не позже датированного потребителя |
| Зависимости | Без циклов и ссылки на себя |
| Батальоны | Уникальны для каждого способа появления, даже альтернативного |

Отдельного числового максимума длины списка текущая проверка требований не задаёт. Ограничения — известные датированные решения, разные ID и отсутствие циклов. Это не рекомендация делать длинные неясные условия: небольшой список проще проверить и проиграть.

## Как работает механизм

Когда production или позднее датированное событие использует решение, компилятор создаёт постоянное общее состояние выбора. Потребитель сначала ждёт разрешения требований, затем запускает соответствующую ветку. Неподходящая ветка не меняет силы. Поэтому «ещё не выбрано» отличается от выбора первого варианта.

Штатные переменные, технические значения ожидания, enum сравнений и ID объектов вручную не редактируются. Публичные настройки — ID события и индекс выбора. Обычный компилятор задаёт ответы ИИ и представления игрока. Кооперативный показ экспериментален; работоспособность одиночной ветки не подтверждает сетевую синхронизацию.

## Разбор проблем

Пропали альтернативы: проверьте оба решения, все требования и сроки групп. Появились оба варианта: проверьте пересечение условий. Переименование кнопки изменило исход: возможно, изменён порядок choices; сохраните индексы или поправьте потребителей. Ошибка предшествующего решения: поставьте датированный источник не позже потребителя. Общий батальон в копиях: копируйте определения, а не только имена групп.
