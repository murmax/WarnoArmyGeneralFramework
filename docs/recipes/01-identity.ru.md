# 1. Идентичность, названия и стороны кампании

[Навигатор](../RECIPES_RU.md) · [English](01-identity.md) · [Справочник файла](../YAML_REFERENCE_RU.md)

## Простой вариант: новое название вашей копии

Сначала создайте независимую копию командой `clone` из [инструкции подготовки](../GETTING_STARTED_RU.md). Работайте в `campaigns/my-campaign`, сохраняя комплектный пример.

1. Откройте `campaign.yaml`, измените корневые `title` и `summary`.
2. Измените существующие `menu.header`, `subtitle`, `description` и обе записи `side_forces`. Они остаются внутри `menu`.
3. Для каждой изменённой английской строки обновите [таблицы переводов](12-localization.ru.md).
4. Проверьте исходники, затем соберите мод и начните новую кампанию.

```yaml
title:
  ru: Оборона побережья
  en: Coastal Defense
summary:
  ru: Удержите порт до прибытия резервов.
  en: Hold the port until reserves arrive.
```

Заменяйте существующие поля: второй блок `title` или `menu` добавлять не нужно.

```powershell
./.venv/Scripts/python.exe -B scripts/campaign.py check campaigns/my-campaign --game $game --output artifacts/identity-check-01
```

Каждая проверка требует нового выходного каталога. Установленный мод она не меняет.

## Собственные названия армий в меню

Добавьте этот необязательный блок **внутрь существующего `menu`**:

```yaml
side_titles:
  nato: {ru: Экспедиционный корпус, en: Expeditionary Corps}
  pact: {ru: Прибрежная армия, en: Coastal Army}
```

При наличии блока нужны обе стороны и оба языка. Это подписи сторон в меню выбора кампании. Они не переименовывают батальоны и не заменяют их технику. Для состава и названий частей см. [батальоны](03-rosters.ru.md), для символики — [иллюстрации и эмблемы](11-artwork.ru.md).

## Другие полезные действия

- Написать развёрнутое описание меню с сохранением абзацев через `|-`.
- Включить несколько поддерживаемых стран в одну коалицию.
- Назначить атакующую сторону для подписей меню.
- Создать самостоятельную кампанию из уже изменённого образца.
- Переименовать отображаемые цели, сохранив их технические ID.

Для нового ответвления:

```powershell
./.venv/Scripts/python.exe -B scripts/campaign.py clone campaigns/my-campaign campaigns/coastal-defense --id coastal_defense
```

Выбирайте новый каталог и ID. Готовую техническую идентичность удобнее менять клонированием, чем согласовывать вручную после сборки.

## Настройки и их расположение

| Где | Допустимое значение | Что меняет |
| --- | --- | --- |
| `campaign.yaml.schema` | `1` | Версия формата исходников |
| `campaign.yaml.id` | Независимый ID, созданный `clone` | Техническую идентичность, а не экранное имя |
| `campaign.yaml.template` | Совпадает с `profile.yaml.id` | Используемый профиль совместимости |
| `title`, `summary` | Непустые строки `ru` и `en` | Название и краткое описание |
| `sides.<side>.countries` | Непустой список поддерживаемых кодов | Допустимые страны батальонов этой стороны |
| `sides.<side>.playable` | Boolean | Декларацию играбельности; текущий шаблон требует обе играбельные стороны |
| `menu.header`, `subtitle`, `description` | RU/EN | Текст карточки кампании; для абзацев используйте блок |
| `menu.side_forces` | Обе стороны, у каждой RU/EN | Описание войск |
| `menu.side_titles` | Необязательно, обе стороны с RU/EN | Названия армий в меню |
| `menu.attacker` | `nato` или `pact` | Подписи атаки/обороны в меню |
| `menu.image` | Относительный путь к широкой PNG | Картинку выбора; ограничения — в [инструкции по изображениям](11-artwork.ru.md) |
| `ai_policy.native_strategies` | Сторона → `attacker`/`defender` | Штатную стратегическую роль ИИ, отдельно от меню |

Если используется `menu`, обязательны `header`, `subtitle`, `description`, `side_forces`, `image`, `attacker`. Необязательная настройка не отменяет остальные обязательные поля.

Для `clone` ID состоит из 1–48 строчных латинских букв, цифр и подчёркиваний и начинается с буквы. Команда согласует идентичности кампании/профиля, токены изображений и независимое имя карты. Технические ID и пути не переводятся.

Адаптер стратегических подставок поддерживает `US`, `RFA`, `SOV`, `RDA`/`DDR`, `UK`, `BEL`, `NL`, `POL`, `CAN`, `ESP`, `FR`, `TCH`, `CUB`. Код страны не создаёт тактические юниты этой страны: выбирайте реальные отряды и транспорт из каталога. Дополнительная страна требует соответствующей возможности адаптера.

## Как это работает

По техническим идентификаторам фреймворк создаёт самостоятельные определения сценария, частей и локализации. Человеческий текст отдельно компилируется в словари. Изменение `title.en` меняет надпись, но не создаёт другую кампанию; `clone` с новым ID создаёт независимые определения даже до переименования меню.

`nato` и `pact` — два внутренних слота коалиций. Их имена не обязывают делать любой сюжет только США против СССР. Страны, фактический состав, текст меню и роль ИИ настраиваются отдельно.

У структуры войск другой уровень именования: `definition.organization_text` описывает полковое/организационное подчинение, `definition.formation.division_text` — общее вышестоящее соединение. Это не названия армий из меню. Подробнее — в [структуре батальона](03-rosters.ru.md).

## Связанные изменения и ошибки

| Что произошло или требуется | Что проверить |
| --- | --- |
| Новое название, старое описание | Измените существующие поля меню и их переводы |
| Перепутаны подписи атаки и обороны | `menu.attacker`; настройки ИИ проверяются отдельно |
| Новая страна не проходит проверку | Страна батальона входит в `sides`; её подставка поддерживается |
| Копии кампаний конфликтуют | Создайте самостоятельную копию через `clone` |
| Нужно изменить ID цели | Одновременно обновите победу, ИИ, события, резервные условия, камеру и концовки: [цели и маршруты](10-objectives.ru.md) |
| Изменённая строка не переведена | Ключ таблицы должен точно совпадать с новой английской строкой |

Изменения идентичности и структуры войск проверяются в новой кампании после [полной сборки](14-build.ru.md).
