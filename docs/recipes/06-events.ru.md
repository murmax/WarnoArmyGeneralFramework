# 6. Автоматические прибытия и эффекты событий

[Навигатор](../RECIPES_RU.md) · [English](06-events.md) · [Карточки резервов](05-reserves.ru.md)

## Простой вариант: автоматическое прибытие

Используйте этот способ, когда часть должна появиться в фиксированной позиции без выбора карточки резерва.

1. Создайте уникальное определение `my_auto_reserve`: [состав батальона](03-rosters.ru.md).
2. Добавьте прибытие в `reinforcements.yaml.reinforcements`.
3. Выберите доступную дружественную позицию и существующий флаг/waypoint назначения.
4. Выполните check/build и дойдите до срока в новой кампании.

```yaml
schema: 1
reinforcements:
- id: arrival_my_reserve
  battalion: my_auto_reserve
  side: pact
  turn: 6
  position: [877500, 331500]
  ai: {type: defend, target: sevastopol}
```

Если файл уже содержит записи, добавьте элемент его списка, а не заменяйте весь файл примером. ID и позиция должны соответствовать вашей карте. Не создавайте этот же батальон другим способом.

```powershell
./.venv/Scripts/python.exe -B scripts/campaign.py check campaigns/my-campaign --game $game --output artifacts/event-check-01
```

## Объяснить игроку прибытие

В `events.yaml.events` добавьте обычное уведомление:

```yaml
- id: reserve_arrival_notice
  side: pact
  trigger: {turn: 6}
  title: {ru: Резервы прибыли, en: Reserves Have Arrived}
  text: {ru: Пехотный резерв прибыл в тыловой район., en: Infantry reserves have reached the rear area.}
  image: null
  choices: []
  effects: []
```

Прибытие и уведомление являются отдельными одноразовыми действиями. Здесь `effects` пуст: часть уже создаёт reinforcement. Второй spawn того же батальона дублировал бы его. Переведите новые строки.

`side` — получатель, а не язык. Уведомление PACT может показываться на английском. Обычному уведомлению разрешён `image: null`; выбору нужна зарегистрированная иллюстрация.

## Появление после решения

В **список `effects` конкретного варианта** добавьте эффект с отдельным определением:

```yaml
effects:
- spawn: my_event_reserve
  position: [877500, 331500]
  ai: {type: defend, target: sevastopol}
```

Сторона события и батальона совпадает. Батальон не должен уже размещаться, находиться в production или другом прибытии. Самолёты связываются через [доступность авиации](09-aviation.ru.md).

Чтобы на ходе 3 выбрать прибытие на ходе 6, событие получает `trigger: {turn: 3}`, а его spawn — дополнительное поле:

```yaml
at_turn: 6
```

Оно находится рядом со `spawn`, `position`, `ai`. Нужен датированный trigger, последующий ход прибытия внутри кампании. Для двух альтернативных районов высадки создайте два разных определения. Одинаковый состав не разрешает повторно использовать один изменяемый штатный батальон.

## Полная структура выбора из двух вариантов

```yaml
- id: reserve_direction
  side: pact
  trigger: {turn: 3}
  title: {ru: Направление резерва, en: Reserve Direction}
  text: {ru: Выберите задачу резерва., en: Choose the reserve mission.}
  image: reserve_choice
  layout: text
  ai_choice: 0
  effects: []
  choices:
  - label: {ru: Удержать порт, en: Hold the Port}
    effects:
    - spawn: port_reserve
      position: [877500, 331500]
      ai: {type: defend, target: sevastopol}
  - label: {ru: Усилить аэродром, en: Reinforce the Airfield}
    effects:
    - spawn: airfield_reserve
      position: [877500, 487500]
      ai: {type: defend, target: belbek}
```

До использования примера объявите оба батальона и логический ID иллюстрации `reserve_choice`: [изображения](11-artwork.ru.md). Варианты имеют индексы 0 и 1; `ai_choice: 0` выбирает первый для ИИ. Поддерживается ровно два варианта. При наличии choices общие `effects` события пусты.

Для иллюстрированных карточек задайте `layout: graphic_cards`, парную составную картинку события и у каждого варианта `card` с логическим `image`, RU/EN `title`, RU/EN `text`. В `layout: text` блок card недопустим.

## Все формы trigger

| `trigger` | Значение и ограничения |
| --- | --- |
| `{turn: 6}` | Однократно на указанном ходе получателя, 1…длительность |
| `{turn: 6, when: [...]}` | Ход с требованиями к прошлым решениям: [условия](07-conditions.ru.md) |
| `{flag: belbek, owner: nato}` | Когда флагом владеет указанная сторона |
| `{capture: belbek}` | После захвата стороной-получателем события |
| `{first_enemy_destroyed: true}` | Первое учтённое уничтожение противника для стороны; не условие по произвольному типу юнита |
| `{capture_deadline: blocked}` | Постоянно закреплённая отмена ранним захватом |
| `{turn: 9, capture_deadline: not_blocked}` | Отсутствие отмены на ходе предела или позже |

`blocked` тоже может иметь дату. Формы deadline требуют `campaign.capture_deadline`; `not_blocked` — ход не раньше его предела. `when` допустим только вместе с `turn`. Произвольно соединять эти формы в новую условную конструкцию нельзя.

## Все эффекты

| Эффект | Поддерживаемые поля | Границы |
| --- | --- | --- |
| Появление | `spawn`, `position`, `ai`, необязательный `at_turn` | Уникальный наземный батальон той же стороны, позиция в profile.bounds |
| Очки | `score`, `side` | Целое −1000…1000, кроме нуля; `nato`/`pact` |
| Текущие ОД | `action_points`, `battalion` | Целое 0–12, первоначально размещённый батальон |
| Потери | `casualties`, `random_range`, `battalion` | Бюджет 1–1000, разброс 0–1000, первоначально размещённый батальон |

Сторона начисления очков может отличаться от получателя уведомления. Потери — штатный бюджет/разброс, а не процент личного состава. Текущие ОД не меняют нормальное восстановление/ёмкость. Общих эффектов `remove`, `end_game`, `camera`, `fatigue`, `unlock` и произвольного скрипта нет; используйте уход авиации, правила победы и стартовые блокировки.

## Как работает механизм

Компилятор создаёт штатные условия, представления и выполнение эффектов. Выбор игрока сохраняет индекс, ИИ использует объявленный вариант. Непосредственное появление следует за решением; отложенное устанавливает позднее условие хода. Резервы и авиация могут потреблять решение собственными полями доступности без немедленных эффектов события.

Заголовок/текст являются локализацией, а не исполняемыми командами. Фраза про прибытие не создаёт часть. Пустое уведомление допустимо; пустой выбор допустим только при реальном поддерживаемом потребителе результата. Подробнее — [условные варианты](07-conditions.ru.md).

Кооперативная синхронизация событий экспериментальна. Перед заявлением кооперативной готовности проверьте показ и завершение событий у каждого участника.

## Разбор ошибок

Не тот получатель: проверьте `side`, а не язык интерфейса. Нет картинки: нужен логический ID, а не путь к PNG. Нет прибытия: проверьте эффект/запись reinforcement, уникальный батальон и trigger. Повторное использование: отдельные определения для альтернативных появлений. Ошибка задержки: `at_turn` только у spawn датированного события и позже trigger. Сюжет изменился, силы нет: задайте реального потребителя решения. Новые события в старом сохранении не появляются автоматически — после сборки начните новую кампанию.
