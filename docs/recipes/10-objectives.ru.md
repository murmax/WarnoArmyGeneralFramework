# 10. Цели, контроль территории, маршруты и концовки

[Навигатор](../RECIPES_RU.md) · [English](10-objectives.md) · [Справочник карты](../YAML_REFERENCE_RU.md)

## Простой вариант: передвинуть существующую цель

1. В `map.yaml.flags` найдите её `id` и измените `position`.
2. Согласуйте `initial_owner` с ближайшими `influence_sources`: перенесите/добавьте дружественный источник, если цель должна находиться за фронтом этой стороны.
3. Отдельно передвиньте географическую подпись в `labels`, если нужно.
4. Проверьте размещения, пункты резервов и waypoints рядом: они не следуют за флагом автоматически.
5. Выполните check/build и проверьте контроль, подходы и подпись в новой кампании.

```yaml
position: [877500, 331500]
```

Это штатные координаты внутри profile.bounds, а не долгота/широта. Выбирайте доступную местность playable area. Преобразование географических точек — в [инструкции географии](13-geography.ru.md).

```powershell
./.venv/Scripts/python.exe -B scripts/campaign.py check campaigns/my-campaign --game $game --output artifacts/objective-check-01
```

## Географическая подпись и невидимая точка маршрута

Флаг и подпись выполняют разные задачи. Название населённого пункта можно сохранять без цели:

```yaml
# В labels
- id: rear_town_label
  position: [1085500, 487500]
  text: {ru: Тыловой город, en: Rear Town}
  size: medium
```

Невидимая цель маршрута задаётся waypoint:

```yaml
# В waypoints
- id: rear_junction
  position: [1085500, 487500]
```

ID подписи или пункта production не является целью миссии автоматически: нужна запись flags/waypoints. `markers` создаёт маленькую подпись по `id`, `position`, строке `name`; одинаковое имя копируется в RU/EN. Для перевода используйте labels.

## Простой вариант: путь стартовой части

В `ai.yaml.orders` используется **ID размещения**:

```yaml
- unit: dep_my_infantry
  type: attack
  target: sevastopol
  start_turn: 1
  route: [belbek, inkerman, sevastopol]
```

Цели примера объявлены в комплектной карте. Каждому стартовому размещению нужен ровно один приказ. Резервы/прибытия получают план в собственных документах: [карточки](05-reserves.ru.md).

Последняя точка совпадает с target. Промежуточные ID — реальные flags/waypoints, а не текстовые названия дорог. Маршрут направляет миссию, но не рисует дорогу и не прокладывает снабжение.

## Параметры миссий

| Поле | Значения / правило |
| --- | --- |
| `orders[].unit` | Существующий deployment ID |
| `type` | `attack`, `counterattack`, `move_to`, `defend`, `hold`, `reserve`, `support`, `air_support` |
| `target` | ID flags/waypoints |
| `start_turn` стартового приказа | Целое ≥1; полезный ход внутри кампании |
| `route` | Необязательно, default `[target]`; стартовые/прибывающие планы — 1–11 разных целей, последняя target |
| Много точек | Для attack/counterattack/move_to; статичные планы используют одну цель |
| `ai_policy.phase_orders` | ID батальона → список from_turn, type, target, необязательного route |

Атака/контратака выражают намерение миссии, move_to — движение. Статичные defend/hold/reserve/support/air_support задают позицию/назначение. Штатная оценка сил, доступный путь, ОД, усталость, контроль и снабжение влияют на реальное выполнение. Приказ не гарантирует атаку при любых шансах.

Для поздней смены плана внутри `campaign.yaml.ai_policy.phase_orders`:

```yaml
my_infantry:
- from_turn: 8
  type: counterattack
  target: sevastopol
  route: [belbek, inkerman, sevastopol]
```

Здесь ID батальона, а не размещения. from_turn строго возрастают внутри кампании. Согласуйте маршрут с объявленными целями и типом движения. Фаза изменяет план с этого срока, а не создаёт вторую часть.

## Все настройки ai_policy

Если блок присутствует, обязательны `attack_radius`, `cooperate`. Сохраняйте рабочую основу и меняйте согласованные группы настроек по очереди.

| Поле | Границы / зависимости | Назначение |
| --- | --- | --- |
| `attack_radius` | Целое 530–2120 | Старый радиус поиска боя в GRU, не клетки |
| `cooperate` | Boolean | Участие ближайших частей в миссиях |
| `refresh_each_turn` | Boolean | Обновление миссий/фаз каждый ход |
| `continuous_route` | Boolean, нужен refresh | Сохранение оставшихся точек маршрута вместе |
| `retain_route_progress` | Boolean, нужен continuous | Фиксация обеспеченного промежуточного продвижения; финальная цель остаётся действующей |
| `aggressive_until` | Сторона → ход 1…длительность, нужен refresh | Боевой профиль миссий Agressif до предела, затем Default |
| `phase_orders` | Известные батальоны, упорядоченные планы | Датированная смена миссии |
| `native_strategies` | Сторона → attacker/defender | Роли штатных стратегических контроллеров |
| `native_controller_sides` | Список разных nato/pact | Штатное управление вместо частных миссий |
| `scripted_exceptions` | Разные батальоны этих штатных сторон | Частные миссии у выбранных исключений |
| `attack_radius_cells` | Конечное >0…12 | Поиск у обычной/финальной цели |
| `transit_radius_cells` | Конечное >0…12 | Поиск у заданных транзитных waypoints |
| `support_radius_cells` | Конечное >0…12 | Тыловые/поддерживающие планы |
| `waypoint_radius_cells` | Конечное >0…12 | Допуск достижения точки |
| `transit_waypoints` | Разные известные waypoint ID, не флаги; нужны клеточные радиусы | Промежуточные точки транзитного поиска |

Задавайте **все четыре** клеточных радиуса вместе при refresh и continuous. Это штатные AP-клетки и проверенное преобразование единиц, а не пиксели текстуры или количество клеток логической сетки автора. Без этого набора старый допуск waypoint — 707 GRU.

`aggressive_until` меняет боевой профиль частной миссии, а не все глобальные правила принятия боя. Штатно управляемые батальоны получают частные runtime-миссии только как exceptions; исходные приказы могут оставаться намерениями автора без создания таких миссий. `menu.attacker` независимо меняет только подписи меню.

## Контроль и победа

| Поле | Значение / смысл |
| --- | --- |
| `id` флага | Уникальный технический ID цели |
| `position` флага | Штатные `[x,y]` в границах |
| `initial_owner` | nato, pact, null |
| `capture_score`, `hold_score` | Целые ≥0; захват и дальнейшее владение |
| `name` | Непустые RU/EN |
| Источник влияния | Точно side, position, числовое value ≥0 |
| `labels[].size` | large, medium, small |
| `campaign.score_to_win` | Положительное целое базового порога |
| `victory.nato_capture`, `pact_capture` | Разные объявленные flags; захват соответствующей стороной завершает кампанию |
| `victory.time_limit` | draw, nato, pact |
| `capture_deadline` | Точно flag, захватывающий owner, before_turn 2…длительность, production division |

Владение стартовым флагом согласуется с ближайшим источником: противоречия/неоднозначность отвергаются. Сила влияния не является очками победы или AP-радиусом. Приезд изолированного юнита к флагу сам по себе не гарантирует захват: действует штатный контроль территории.

Текущий `production.required_flag` отличается от постоянной ранней отмены. Capture deadline закрепляется при контроле флага захватывающей стороной до предела; последующий перезахват дивизию не возвращает. Её группам нужны планы ИИ и прибытие не раньше предела. Подробнее — [резервы](05-reserves.ru.md).

## Камера, вступление и концовки

В `cinematics.yaml`:

```yaml
start_camera:
  focus: sevastopol
  altitude: 900000
  north_up: true
```

Focus — ID флага, altitude — конечные штатные 100000–2000000. Ориентация камеры не поворачивает и не геопривязывает растр.

В файле обязательны вступления обеих сторон ровно по четыре слайда и все варианты концовок. Слайд: RU/EN title, text, логический image; необязательный RU/EN voice_script — текст диктора, а не готовая озвучка. Необязательный layout — briefing, layout_version — 1/2, где 2 разделяет изображение и текстовую область.

Для другой географии явно привяжите существующие флаги:

```yaml
ending_flags: {city: main_city, landing: beachhead, inland: rear_hub}
encirclement_flags: [north_gate, south_gate]
```

City/landing/inland различаются. Явные ending_flags требуют явного непустого списка разных encirclement_flags. Технические ключи осей сохраняются:

| Ось | Обязательные варианты каждой стороны |
| --- | --- |
| result | victory, stagnation, defeat |
| sevastopol | taken, surrounded, held |
| invasion | lost, beachhead, breakthrough |

При завершении выбираются три слайда. Город: контроль НАТО → taken; иначе все флаги окружения за НАТО → surrounded; иначе held. Вторжение: landing за PACT → lost; иначе landing и inland за НАТО → breakthrough; иначе beachhead. Result следует реальному завершению. Текст правило победы не задаёт. Без явной привязки используются sevastopol, kacha_beach, simferopol комплектного примера; при другой географии задайте собственные связи.

## Механизм и ошибки

Отдельно создаются штатные цели/влияние, подписи, теги пути, миссии, камера и условия концовок. Общие ID связывают их, но не объединяют назначение. Экранное имя меняется отдельно; при смене технического ID обновляются события, резервы, победа, камера, концовки и ИИ.

Пассивный ИИ: сначала проверьте состояние, стартовый/прибывающий план, координаты и режим контроллера. Неверный фронт: влияние, а не только текст флага. Целью служит подпись: объявите waypoint. Неверная концовка: проверьте связи/владение, а не только текст слайда. Правки карты и миссий оцениваются в новой кампании.
