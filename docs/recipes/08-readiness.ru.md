# 8. Начальное состояние, потери и временная блокировка

[Навигатор](../RECIPES_RU.md) · [English](08-readiness.md) · [ОД поддержки](04-support.ru.md)

## Простой вариант: блокировка на два хода

1. Найдите запись части в `deployments.yaml` по ID размещения или ссылке на батальон.
2. Измените `frozen_turns` на 2.
3. В `definition.initial_state` батальона оставьте положительные нормальные ОД, например 10.
4. Согласуйте текущие ОД стартового размещения с этой ёмкостью.
5. Выполните check/build, начните новую кампанию и дойдите до освобождения.

```yaml
# Внутри definition батальона
initial_state: {fatigue: 0, action_points: 10}
```

```yaml
# Поля существующего размещения
fatigue: 0
action_points: 10
frozen_turns: 2
```

```powershell
./.venv/Scripts/python.exe -B scripts/campaign.py check campaigns/my-campaign --game $game --output artifacts/readiness-check-01
```

Отсчёт идёт по ходам владельца: 2 блокирует первые два, освобождение наступает на третьем. Это не двухчасовой таймер. Постоянные нормальные ОД не обнуляйте для имитации блокировки.

## Три разных настройки

| Поле | Смысл |
| --- | --- |
| `definition.initial_state.action_points` | Нормальные начальные/восстанавливаемые ОД наземной/вертолётной части |
| `deployments[].action_points` | Текущие ОД при первом размещении на карте |
| `deployments[].frozen_turns` | Временная блокировка со штатным отсчётом и освобождением |

Для нормальных 5 ОД поддержки задайте 5 в определении. Пять текущих ОД в deployments при нормальных 12 — только стартовое ограничение; восстановление следует определению. Самолётам задаётся штатная политика 4/4 независимо от AP-переопределения в этом блоке определения.

Для первоначально размещённой наземной части усталость задаёт deployment. Для резервов и прибывающих самолётов — `initial_state.fatigue` уникального определения.

## Потрёпанная или уставшая часть

Усталость: **0 — свежая часть, 8 — истощённая**. Больше — хуже состояние, а не выше мораль. Для стартовой части поставьте `fatigue: 2` в deployments, для резерва — в определении.

К существующему наземному размещению добавьте ограниченные потери:

```yaml
initial_losses:
  max_percent: 25
```

Ограничение вычисляется по составу, а не устанавливает точный экранный процент. Потери, усталость и блокировку можно сочетать, но это независимые механизмы. Предел потерь 25% не гарантирует одинаковую полосу готовности 75% у неоднородных составов.

Альтернатива — штатный бюджет:

```yaml
initial_losses:
  budget: 40
  random_range: 0
```

Выберите одну форму. Бюджет/разброс не являются процентами. Нулевой разброс фиксирует разброс бюджета, но не выбор конкретных потерянных юнитов.

## Полная запись размещения

```yaml
- id: dep_my_infantry
  battalion: my_infantry
  side: pact
  position: [877500, 331500]
  fatigue: 2
  action_points: 10
  frozen_turns: 2
  initial_losses: {max_percent: 25}
```

Нужно объявленное уникальное наземное определение той же стороны с положительными нормальными ОД. В `ai.yaml` добавьте ровно один стартовый приказ на `dep_my_infantry`, а не на `my_infantry`: например defend, существующая дружественная цель, `start_turn: 1`. Приказ не отменяет блокировку.

## Все настройки

| Где | Допустимые значения |
| --- | --- |
| Корень deployments | `schema: 1`, список `deployments` |
| Обязательные поля размещения | Уникальный `id`, известный `battalion`, совпадающая `side`, допустимая `position`, `fatigue`, `action_points`, `frozen_turns` |
| `fatigue` размещения | Целое 0–8 |
| `action_points` размещения | Неотрицательное целое; выбирайте в пределах нормальной ёмкости |
| `frozen_turns` | Неотрицательное целое; 0 — без блокировки |
| `definition.initial_state` | Необязательный непустой блок с fatigue и/или action_points |
| Усталость определения | Целое 0–8; обычно по умолчанию 0 |
| ОД определения | Целое 0–12; наземный default 12, у самолётов генерируется 4 |
| Потери deployment `max_percent` | Целое 0–99; нужен явный авторский состав |
| Потери deployment `budget` | Неотрицательное штатное целое |
| Потери deployment `random_range` | Неотрицательное, ≤budget; сумма ≤2³¹−1 |
| Потери прибытия авиации | `aviation.wings[].initial_losses.max_percent`, целое 0–99 |

Отдельной верхней границы `frozen_turns`, связанной с длительностью, нет. Для временной блокировки выберите освобождение до конца кампании; иначе часть останется закрытой всю игру. Формы потерь необязательны: отсутствие означает отсутствие заданных стартовых потерь.

## Устройство механизма

Нормальные ОД/восстановление компилируются в модули состояния части. Стартовое размещение задаётся отдельно. Ненулевая блокировка создаёт штатное закрытое состояние и цепочку отсчёта, которая запрещает раннее действие и освобождает по ходам владельца, сохраняя нормальное восстановление.

Потери стартовой части применяются один раз при начале кампании, авиационные — после прибытия. Бюджет расходуется на элементы состава с их штатными весами; это не точный процент солдат, стоимости техники или полосы состава. Поздние [события](06-events.ru.md) могут менять текущие ОД и наносить потери первоначальным частям, но общего поля fatigue/unlock не предоставляют.

## Разбор проблем

Постоянные 0/0 ОД: проверьте нормальную ёмкость/восстановление, используйте положительные ОД и поле блокировки. Неверное состояние первого хода: сверяйте definition и deployment. Свежий резерв вместо уставшего: настройте усталость определения. Непонятный процент потерь: различайте ограниченный процент, штатный бюджет и экранную готовность. Правка не изменила сохранение: начните новую кампанию; сериализованное состояние не исправляется автоматически новым YAML.
