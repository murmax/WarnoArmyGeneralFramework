# Практические изменения на примере Качи

[Подготовка и сборка](GETTING_STARTED_RU.md) · [Все поля](YAML_REFERENCE_RU.md) · [English](RECIPES.md).

Работайте в копии `campaigns/my-campaign`, созданной командой clone. Примеры ниже относятся к её файлам. После каждого набора связанных изменений запускайте check с новым каталогом результата. Включённый файл localization.yaml требует обновления всех языков после изменения английской строки.

## 1. Переименовать кампанию и стороны

В campaign.yaml измените `title`, `summary` и все меню-поля RU/EN. Технический id уже изменил clone; название в меню не меняет идентичность. Для собственных названий армий:

```yaml
side_titles:
  nato: {ru: Экспедиционный корпус, en: Expeditionary Corps}
  pact: {ru: Прибрежная армия, en: Coastal Army}
```

Этот блок помещается **внутрь menu**, не в корень. Измените countries для фактических стран, но tactical-юниты и подставки тоже должны соответствовать выбранным силам. `menu.attacker` управляет подписью в меню; `ai_policy.native_strategies` — штатной ролью ИИ.

Для другой главной цели можно оставить внутренний ID `sevastopol` и переименовать только человеческий текст. Если меняете сам ID, обновите victory, AI, события, камеру, production.required_flag и cinematics.ending_flags; одному label недостаточно.

## 2. Продлить кампанию и изменить даты

Измените `turns: 20` на нужное целое, например 24. Старые подкрепления останутся на прежних ходах; продление не пересчитывает их автоматически. Для новых дат меняются `production.groups[].turn`, `reinforcements[].turn`, event.trigger.turn, aviation.available/withdraw_turn и AI phases.

Не переносите группу блокируемой дивизии раньше `capture_deadline.before_turn`. ID `sov_turn11` не заставляет прибыть на 11-м ходу: у актуального примера эта группа имеет `turn: 10`. Меняется число **turn**. Затем согласуйте narrative-текст, который обещает сроки и оставшиеся часы операции.

## 3. Изменить существующий батальон

В battalions/forces.yaml найдите `id: sov_880`. Разверните его companies, затем нужный platoon.units. Например, замена `count: 3` на 4 добавляет один roster-элемент этого pack, а не ещё одну роту. При number 1 это ещё один отряд/машина; при number 2 каждый элемент содержит две.

Чтобы улучшить опыт или заменить транспорт только этого взвода:

1. Найдите используемый type в packs.yaml.
2. Скопируйте **полную запись pack** с новым id, например `my_880_rifle_btr80`.
3. Задайте нужные unit/transport/experience/number по каталогу.
4. Поменяйте type только в нужных взводах на новый id.

Если изменить старую общую запись pack, поменяются и остальные части, использующие её. Для замены танков выбирайте реальный tactical-ID из units.csv и pack из packs.csv или создайте свой; одно отображаемое название роты не заменяет машины.

## 4. Командование, ПВО, артиллерия и снабжение

Для штаба копируйте структуру штабной роты `sov_810_hq` или `us_2md_hq`, затем заменяйте реальные packs по каталогу. Командный взвод имеет `hq: true`; рота управления тоже может быть штабной. Нужны именно командные машины/отряды: флаг HQ не добавляет свойства командира пехоте автоматически.

Добавление FOB и 10 машин снабжения — обычные entries в units: pack для FOB с count 1, pack машины снабжения с number 1/count 10. Не существует поля `supply: 10`. Для вертолётной части подбирайте соответствующие командные/транспортные/снабжающие вертолёты, не случайные наземные КШМ.

У артиллерийского батальона:

```yaml
strategic:
  type: mechanized
  battle_role: ground_support
  visual: {unit: 2S1_Gvozdika_Naval_SOV}
  icon: howitzer
  support: {kind: artillery, radius_ap: 12}
initial_state: {fatigue: 0, action_points: 5}
```

Для ПВО: `battle_role: auxiliary_support`, `icon: AA`, kind air_defence и реальная модель ПВО. Current AP на старте задайте согласованно в deployments. Постоянное восстановление 5/4 задаётся в initial_state, не только начальная цифра на карте. Радиус — стратегическая AP-шкала. Это не обещание, что ИИ всегда правильно развернёт поддержку.

## 5. Сделать новый батальон подкреплением

1. Скопируйте **весь** объект `sov_885`, включая definition/companies, в том же battalions-списке или новом файле с schema 1/battalions.
2. Дайте ему `id: my_reserve`; поменяйте короткие имена и состав. Вложенные company/platoon IDs могут повторяться у разных батальонов.
3. Не добавляйте его в deployments и не копируйте стартовый AI-order.
4. В production.groups добавьте:

```yaml
- id: my_reserve_card
  division: sov_810
  name: {ru: Резервная группа, en: Reserve Group}
  turn: 6
  battalions: [my_reserve]
  ai: {type: defend, target: sevastopol}
```

5. Добавьте переводы новых строк. Если должны прибыть несколько частей одной карточкой, создайте отдельные уникальные battalion-объекты и перечислите их в этом battalions-списке.

Ссылка на division использует существующие пункты развёртывания. Для собственного пункта добавьте deployment_points-запись той же стороны и её id в division.deployment_points. Не оставляйте неиспользуемый пункт/дивизию. За игрока это резервная карточка, за ИИ действует его план.

## 6. Автоматическое прибытие или прибытие после решения

Для автоматического появляющегося батальона используйте reinforcements.yaml с id/battalion/side/turn/position/ai. Для появления после нажатия кнопки добавьте effect в соответствующую choice:

```yaml
effects:
- spawn: my_event_reserve
  position: [851500, 331500]
  ai: {type: defend, target: sevastopol}
```

`my_event_reserve` должен быть отдельным определением; не повторять my_reserve из production. Для отложенного появления добавьте `at_turn: 6` к effect датированного события, с trigger.turn раньше 6. Самолёты так не создаются: их связывает авиационный available.

Если две кнопки размещают похожую часть в разных местах, создайте два состава с разными ID, как SEAL в Каче. Нельзя спаунить один descriptor из двух вариантов даже при взаимоисключающем выборе.

## 7. Изменить сложность без случайной потери танков

В events найдите nato_difficulty/pact_difficulty. Первый вариант — choice 0 (обычный), второй — choice 1 (суровый); ai_choice остаётся 0. Событие игрока само по себе не меняет страну противника.

В production существуют разные уникальные силы для каждой ветви:

- обычная группа `us_turn5`: оба решения 0;
- группа `us_turn5_hard_pact`: NATO 0, PACT 1;
- группа `us_turn5_hard_nato`: NATO 1, PACT 0;
- аналогичные отдельные группы на 7-м ходу.

Меняйте нужную группу и её батальоны, проверяя when целиком. Условия соединены И; инверсия одной choice изменит реальную доступность. Для нового различия состава сначала копируйте батальон с уникальным id, затем привязывайте только к своей карточке. Тексты события объясняют ситуацию, но не являются настройкой сил.

## 8. Заблокировать гарнизон на два хода

В deployments нужной части задайте `frozen_turns: 2`, оставив нормальную ёмкость и восстановление в battalion.initial_state, например 10 ОД. После освобождения часть становится обычной.

Не используйте permanent action_points 0 и не имитируйте блокировку бесконечным supply-malus. В старом сохранении прежняя 0/0 ёмкость не исправляется новым YAML — начните новую кампанию.

## 9. Сменить авиационную развилку

В составе авиакрыла измените реальные aircraft packs и strategic.aircraft_role. Далее свяжите его в aviation.wings с `available: {event: sov_air_choice, choice: 0}` или 1. Названия, emblem/formation, picture и текст решения обновляются отдельно.

Для самолёта ППВО выберите SEAD-tagged tactical-юнит и aircraft_role sead. Для поддержки bomber разрешены бомбардировщики и Avion_AT. Морпеховское подчинение не становится правильным лишь потому, что авиация помогает морпехам: задайте отдельную formation/эмблему ВВС.

При изменении withdraw_turn в aviation также обновите дату и смысл carrier-notice в events. Если должны уйти несколько крыльев, withdraw_turn нужен у каждого. Сам notice не удаляет оставшийся SEAD.

## 10. Перенести флаг, город и маршрут

Позиция victory-флага меняется в map.flags. Географическая надпись — map.labels. Начальные части — deployments.position; точки резервов — production.deployment_points.position; waypoints — map.waypoints.position. Они не перемещаются автоматически вместе с текстом города.

Проверьте ближайшие influence_sources и initial_owner. Если новой позицией должен управлять PACT, рядом нужен источник PACT. AI target остаётся ID цели, а не строкой на экране. Для одного батальона через Бахчисарай можно использовать route `[bakhchysarai, inkerman, sevastopol]`; обе промежуточные точки должны существовать.

Если меняете главные цели на новые ID, задайте явные cinematics.ending_flags и encirclement_flags, переназначьте victory и start_camera.focus. Технические ключи endings.sevastopol/invasion остаются именами осей, а не названиями города.

## 11. Поменять картинки и эмблемы

Замените исходный файл по пути event-images.images или добавьте новый логический ID и PNG. Для нового ID зарегистрируйте profile.event_images token по формуле `AGF_EVT_<namespace>_<id>`; использующий его event/slide получает этот логический ID. Для парных карточек меняется composites.cards и choices[].card.image.

Картинка меню — campaign.menu.image, широкая PNG. Эмблема — emblems token/image и formation.emblem. Национальный флаг на карте — отдельный ресурс игры, не этот шеврон. Используйте реальный оригинал и сохраняйте авторство/лицензию в ASSET_CREDITS.md; ссылка на Wikimedia не заменяет сам исходный PNG, нужный сборке.

## 12. Обновить переводы

После правки английского имени/текста найдите старую точную строку во всех таблицах localization.yaml и замените ключ новой строкой. Перевод тоже измените по смыслу. Для коротких названий заранее подберите естественное сокращение ≤30 UTF-16 в каждом языке.

Не обрезайте весь текст вступления до 30 знаков — у него другой UI. Не переносите имена рот на RU только в поле name и оставляйте name_text/en старым: явное локализованное поле имеет своё назначение.

Если намеренно разрабатываете только RU/EN, можно исключить localization.yaml из своей копии; остальные языки будут EN fallback. Не называйте такой мод полностью переведённым. Публикуемая Кача содержит все семь языков.

## 13. Новый рельеф, лес и населённые пункты

Для той же географии заменяйте heightmap.png/surface.png и placements мира, сохраняя согласованную ориентацию. Лесные/городские AP-клетки сами не создают scenery; добавьте реальные objects по каталогу. Один object — одно размещение, поэтому для плотного квартала нужны разные id и разные позиции.

Для новой географии можно получить исходные raster-файлы по координатам:

```powershell
./.venv/Scripts/python.exe -B -m warno_ag geodata-import 32.45 44.28 34.15 45.55 artifacts/my-geodata-01 --cache artifacts/geodata-cache --resolution 2048 --surface-size 4096 --elevation-ceiling-m 1200
```

Координаты здесь — west/south/east/north **географического импорта**, а не позиции батальона. Команда загружает нужные геоданные и сохраняет provenance. Копируйте подготовленные height/surface-изображения в artwork, обновляйте world.file ссылки и геопривязку по отчёту. Проверьте фактические названия созданных файлов в отчёте, не подставляйте путь к папке как картинку.

Затем обновите исходные города/флаги/фронт/маршруты/части/пункты подкрепления под новую местность; старые координаты Качи не привязываются автоматически к новой карте. Пересоздайте весь список cells или удалите его для временной равнинной сетки. При изменении размеров согласуйте world bounds/render_cases и profile; world при bake начинается в [0,0] с шагом render-case 655360. Высоты держите ниже 5000 игровых единиц. Для изменённого мира используйте новое согласованное map_name, чтобы не принять старый кэш.

## 14. Что сохранить перед сборкой

Сохраните все YAML, нужные изображения и атрибуцию. Выполните check в новом каталоге. Устраните все указанные ошибки ссылок/переводов. Соберите полный пакет, затем установите его штатным installer-командованием из getting-started и начните новую кампанию.

Не требуется вручную редактировать NDF, GUID, бинарные архивы или исходники Python. Если задуманного эффекта нет в справочнике, он ещё не является публичной возможностью: сначала нужна доработка механизма, а не догадка о названии поля.
